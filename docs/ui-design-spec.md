# 界面规范

## 状态与适用范围

本文件记录现有 Web 工作区的公共交互、SF-002 任务、SF-003 个人项目及 SF-004 任务模板要求。功能是否完成以对应功能目录中的验收证据为准；可见演示界面不等于已有后端能力。

## 已有基础

- 布局使用现有桌面侧栏、移动底部导航与可滚动主内容区域。
- 使用 `apps/web/app/globals.css` 中的 `--surface`、`--ink`、`--muted`、`--line`、`--wash`、字号与间距变量；延续黑白灰工作区，不为单页另建视觉体系。
- 正文使用系统中文字体；长回复使用适合阅读的行高，Markdown 代码与表格在内容区域内滚动。
- 可操作控件保留清晰的键盘焦点、可访问名称和禁用状态；图标辅助文字，不承担唯一语义。
- 普通聊天与 Agent 配置已经接入真实服务；资料库仍为演示，文件、检索、团队与插件管理不得描述为已交付。

## SF-002 任务交互

以下要求随 SF-002 实施，实际验收见 `docs/specs/SF-002-personal-tasks/changes.md`。

- `/inbox` 只展示真实任务。待办/已完成数量依据完整列表；搜索当前视图的名称和目标，不改变总数量。
- 创建表单按名称、目标、Agent 排列；字段有显式标签及就近错误；保存不调用模型，成功后进入稳定详情地址。
- 详情持续展示目标、所用助手/模型及工作状态。开始执行、生成中、已停止、失败、任务完成具有不同文案与操作。
- 完成是用户判断；回复结束不会自动完成任务。完成后历史可读，恢复到完成前状态后继续原上下文。
- 模型运行时可停止，工作状态修改暂不可用；停止按钮与保存结果反馈清晰。失败保留输入、已有消息和可恢复入口。
- 任务中使用创建时的 Agent 快照；不显示会让用户误以为可更换旧任务模型/工具的控件。
- 明确区分空列表、无搜索结果、正在加载和服务失败；失败有重试，不用演示卡片掩盖错误。
- memory 模式持续说明重启服务会清空任务及对话；PostgreSQL 模式说明已保存，不承诺尚未验证的能力。
- 390px 宽度下核心字段和按钮可操作，不依赖横向滚动；长标题、目标和工具结果可换行；移动触控区保持足够尺寸。

## 后续要求

共享项目、成员权限、流程模板、文件上传与知识检索仍需各自规格和验收；本文件不将这些能力标为现有实现。

## SF-003 个人项目交互

以下要求随 SF-003 实施，实际验收见 `docs/specs/SF-003-personal-projects/changes.md`。

- 桌面侧栏、移动导航抽屉与底部导航均提供“项目”入口，项目详情保持选中状态；移除“产品与设计”“日常工作”两个演示项目分组，不自动生成真实项目。
- `/projects` 展示当前范围内的全部真实项目，按项目更新时间倒序；搜索匹配项目名称与说明，区分空列表、无匹配、加载和失败状态。创建与编辑表单采用同一名称/说明校验，错误就近显示，保存失败保留输入。
- 重复项目名称允许存在。列表、详情及归属选择器展示稳定编号；选择器同时使用说明或短编号帮助区分同名项目。
- `/projects/[id]` 展示项目说明、全部关联任务、总数及四类工作状态数量。已完成任务同样有原任务链接；空项目各计数为零，不增加项目完成状态。
- 归入已有任务的选择器包含未归组与其他项目任务，明确提示移动来源；生成中的任务禁选。移出任务后仍能在个人任务入口找到原任务。
- 项目内新建任务复用 `/inbox` 的名称、目标、Agent 表单、错误反馈及创建动作标识，将初始归属随同一次创建保存；创建成功后进入稳定任务地址，仍须明确点击“开始执行”。
- 任务详情展示当前项目和返回链接，允许保存移动或选择“未归组”移出。归组期间与生成、状态修改互斥；仅收到确认响应后更新任务、归属和项目数量，失败保留上次确认的显示并提供重试。
- 项目列表、详情和任务详情先建立签名身份，再读取范围内记录。归属管理保留任务目标、冻结 Agent、工作状态和历史；项目说明只作为管理信息，不显示为任务共享上下文。
- memory 模式明确提示服务重启清空项目、任务和对话。项目表单、状态计数、归入选择器、任务列表及移动控件在 390px 下纵向排布，核心控件无需横向滚动；原 `/inbox` 继续显示全部个人任务。

## SF-004 个人任务模板交互

以下要求随 SF-004 实施，实际验收见 `docs/specs/SF-004-project-task-templates/changes.md`。

- 桌面侧栏和移动抽屉提供“任务模板”入口，模板详情与新建页保持当前导航状态。760px 以下的抽屉保留完整页面导航，包含底栏未列出的任务模板；不因底部导航已存在而隐藏页面链接。移动底部仍为五项导航，也可从“项目”页的“任务模板”按钮进入完整模板管理。
- `/templates` 仅展示当前范围保存的真实模板，按更新时间倒序，支持名称及说明搜索；数量、版本、短编号和稳定详情链接可辨认。空列表、无搜索结果、加载与服务失败使用不同反馈，失败可重试。
- `/templates/new` 与 `/templates/[id]` 使用完整编辑器：模板名称 1–120 字、说明最多 2000 字，保留 1–8 项有稳定标识的任务；任务名称 1–120 字、目标 1–8000 字，全部目标合计最多 32000 字。添加、移除、上移和下移保留现有任务标识与内容。
- 字段在失焦或提交时使用共享契约校验，错误靠近关联标签，提交无效时聚焦首个字段。边界按钮禁用并说明最少/最多条目要求；顺序只是清单排列，各任务独立开始和对话。
- 编辑器预览展示全部有序任务目标和助手选择。启动仅针对已保存版本，草稿未保存或版本冲突时明确说明原因并禁用启动。实际模型、提示词、工具及开场消息在生成项目时解析并冻结。
- 启动对话框展示已读取版本、完整任务目标、助手选择、新项目名称和说明；确认只创建项目与未开始任务，不自动运行模型。成功收到完整结果后才跳转到新项目；无模型密钥仍可保存模板和生成项目。
- 模板创建与启动按规范化参数保留动作标识，响应失败后可以原参数重试；关闭再打开启动预览仍保留新项目字段与原动作。编辑失败保留草稿，版本冲突提供明确重载入口；覆盖未保存草稿前有保留或放弃选择。
- 启动版本冲突时，用户明确重读模板后重新检查完整清单，再确认创建；新项目名称和说明保留，不静默换用新版本或自动提交。
- 模板生成项目展示来源模板、生成时版本、原任务条目编号及链接。保持服务返回的原模板顺序；归属变更后原模板任务仍按原编号排序，后续归入任务列在末尾。
- memory 模式明确提示服务重启清空模板、项目、任务和对话。390px 下编辑、排序、预览、启动和项目字段可通过纵向滚动及键盘操作，核心控件无需横向滚动。模板市场、上下游、自动接力、团队负责人和云环境初始化仍属后续范围。
