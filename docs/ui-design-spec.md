# 界面规范

## 状态与适用范围

本文件记录现有 Web 工作区的公共交互与历次功能规范。当前项目含义以 SF-021「个人项目文件夹与项目资料聊天」为准，替代 SF-003 任务归组、SF-016 团队项目、SF-017 协作进度、SF-020 共享看板及 SF-004/SF-018 中依赖旧项目的启动行为。未退役的普通聊天、独立同事消息、任务、账户/模型、资料处理、工作空间与 Skills 仍遵守各自边界。下文标注历史的章节只供查阅，不作为恢复旧功能或保存已授权删除数据的依据；功能是否完成以对应功能目录的实际验收证据为准，可见界面不等于后端能力或最终验收通过。

## 已有基础

- 布局使用现有桌面侧栏、移动底部导航与可滚动主内容区域。
- 按官方 Sidebar 断点，桌面端（768px 起）隐藏通用共享顶部栏，由侧栏提供导航；项目内聊天另在右侧主内容顶部提供项目名称与资料工具栏。767px 及以下保留顶部栏、导航 Sheet 与移动底栏，项目资料按钮在聊天顶部最右侧。
- 桌面侧栏与移动导航 Sheet 的主导航从“开始新对话”人工动作开始，移动底栏首项使用同一动作；主导航依次为 Agents、Skills、资料库、任务模板、任务，不再有旧“项目”页面链接，侧栏统一使用 SidebarMenuButton 的默认样式、图标与文字排列。本人点击后清空当前聊天草稿、提及和选中会话，回到无项目归属的通用助手空白聊天；不删除历史、不取消后台生成、不自动执行模型。空白对话仍在发送第一条非空消息时才创建真实会话，后续消息继续使用该会话；跨页面点击也遵循同一边界。
- 侧栏与手机导航 Sheet 在“全部对话”上方直接列出各个个人项目名称，不单独展示“消息”入口；“全部对话”仍包含项目内聊天，并且默认展开，允许本人手动收起或重新展开；会话按 `updatedAt` 从新到旧排序。首次读取、发送消息、流式回复和后台历史同步后保持这一顺序，打开旧对话本身不将其置顶。
- 侧栏、移动导航 Sheet 与底部导航的页面链接在切换等待期间立即显示加载图标并播报目标页面；路由加载占位只出现在主内容区，保留工作区导航。加载不是空列表或读取成功，完成后才显示目标页的真实数据状态；减少动态效果偏好下禁用占位和图标动画。
- 当前视觉基础为基于 shadcn/ui / Base UI 的 Orbit 简洁主题，沿用语义 token、variants、键盘行为及私有 Portal；2026-10-22 组件设计语言与全站落地的视觉要求见下文。SF-010 的 Base Nova / Neutral 默认外观保留为历史迁移记录，当前共享组件外观以本节为准。旧 `--surface`、`--ink` 主题不恢复。
- 正文使用本地 MiSans，代码保留系统等宽字体；长回复使用适合阅读的行高，Markdown 代码与表格在内容区域内滚动。
- 独立同事开场、转告与其他普通消息沿用回复的段落和列表间距；原文单换行只在段落内部保留，不把 Markdown 块之间的结构换行显示成额外空白行。代码块仍保留换行与缩进。
- 可操作控件保留清晰的键盘焦点、可访问名称和禁用状态；图标辅助文字，不承担唯一语义。
- 普通聊天与 Agent 配置已接入真实服务；全局资料处理按 SF-007、独立向量召回调试按 SF-008、团队成员按 SF-015 验收。项目内 Agent 按问题只读查阅本项目资料按 SF-021 验收；这不表示全局资料库已自动注入所有聊天，也不把插件管理描述为已交付。

## SF-021 个人项目文件夹与项目资料聊天（2026-10-22，当前项目约定）

本节对应 `docs/specs/SF-021-project-folders/`，项目是本人当前工作空间内的私有文件夹，收纳普通对话和上传资料。新项目不从旧项目迁移，也不承担成员、任务归组、上下游、工作进度或看板。手机底栏保持五项：开始新对话、资料库、Agents、任务模板、任务；个人项目从导航 Sheet 中展开。实际交付证据以该功能 changes 为准。

- **侧栏与新建**：保持 256px 侧栏及品牌/空间选择/账户位置，移除独立“消息”入口；在“全部对话”之前放“新建项目”动作，随后直接列每个项目名与原 Folder 图标，无“项目 → 项目名 → 对话”总折叠层。各项目独立展开/收起，列表仅显示精确归属该项目的普通对话；长名保留完整可访问名称。名称必填、最多 120 字；创建 Dialog 失败保留输入及同一请求标识，服务确认后才加进列表。创建项目和展开列表不执行模型或创建聊天。
- **项目内新对话**：每个项目行提供有名称的“新建对话”图标按钮；支持鼠标悬停的精确指针设备上，右侧展开指示与新建对话图标平时隐藏，鼠标移入该行或键盘焦点进入该行后显示，保留原布局位置；触屏设备常显。点击进入该项目的普通空白草稿；首次本人发送非空消息才保存普通会话及项目归属。选择助手仍使用现有菜单和冻结快照；项目内改选助手产生同项目的新草稿。全局“开始新对话”清除项目选择，既有后台生成继续；项目之间切换不把迟到结果、失败重试或未发送文字写进另一项目。第一版不提供对话移入、移出或跨项目移动。
- **输入框项目选择**：底部操作栏在助手选择右侧提供同样式的项目下拉菜单，列出当前本人工作空间的真实项目及“不选择项目”；长名称截断但保留完整名称，手机可用且不挤占发送按钮。只允许新对话草稿选择，保留输入文字、提及与助手；切换不创建记录或执行模型，首次发送才沿既有创建动作保存归属。已有对话显示原项目归属并禁用选择，生成、失败待重试、历史读取及路由解析期间同样禁用；失败重试保持原项目及请求标识，避免重试写入另一项目。
- **同一普通聊天**：项目列表和“全部对话”打开同一会话身份、消息、Agent 及生成状态；“全部对话”包含项目内对话。右侧继续使用既有 Session、阅读排版、底部输入器、发送/停止及失败重试，不添加 Task、责任节点、进度或额外回复框。同项目聊天之间不自动合并历史，不把项目中的其他会话作为资料读取。
- **右上角资料入口**：项目内已有聊天和空白项目草稿均在右侧聊天最右上角提供“打开项目资料”图标。桌面工具栏左侧显示当前项目名；手机将资料图标放在原顶部栏最右侧。点击打开名为“项目资料”的右侧 Sheet，标题下显示项目名及简短用途，关闭沿用 Escape、私有 Portal 与焦点返回。切项目时重置资料面板，账户/工作空间变化清除旧范围内容。
- **资料列表与上传**：Sheet 内提供原生文件选择、格式/10 MiB 限制与“上传资料”操作，支持 TXT、MD、PDF、DOCX，沿用受限解析和默认 Unicode 分片设置。文件与当前项目关系持久保存；失败保留文件和上传动作供重试，不产生重复文件。成功仍留在资料面板，显示真实已上传/处理中状态，不启动聊天模型。列表每页 20 项，提供分页、刷新以及加载/空态/失败/重试；排队、处理中、可供 Agent 查阅、处理失败分别说明，不以分片完成冒称向量索引完成。
- **查看来源**：已处理文件提供“查看资料”，进入 `/rag/[id]?projectFolderId=[folderId]` 的原资料详情；Agent 引用链接另带 `chunk`，定位实际文件分片。项目来源页不展示独立向量索引卡、配置要求或检索调试入口，仍保留原文、下载和分页；普通全局资料页维持原向量功能。详情、原件与分片请求沿用同一项目范围；正文按不可信纯文本呈现，不执行其中代码或外链。来源显示文件名，不能用全局资料或其他项目文件冒充当前来源。
- **Agent 按需查阅**：本人在项目聊天发送问题后，Agent 可主动通过只读查找/读片工具查阅本项目已完成处理的文件，不要求每轮手选资料或另配 embedding 凭据。查找与读取有明确边界及分页，不将全部文件全文无条件塞入每轮上下文；无匹配、未处理或读取失败如实说明。回答使用资料时提供可打开的精确来源。模型无法指定其他账户、工作空间、项目、任意路径或 URL；资料中的文字不构成指令、联络请求、确认、批准、共享或额外工具授权。
- **旧功能退役**：移除原主导航项目链接、旧 `/projects` 列表/详情、任务归组、项目成员、共享资料发布、责任进度及看板；旧链接明确失效，不导航到无关聊天。原个人/流程模板定义及可用编辑功能保留，但依赖旧项目的预览/启动已关闭，界面显示“暂不可启动”，不再出现启动 Dialog 或跳转到旧项目。保留独立同事消息不代表保留旧项目交接或节点能力。
- **数据与验收边界**：用户已明确授权删除旧项目及其真实关联聊天、journal、资料/成果版本和相关执行记录；仅隐藏入口不能满足删除。按真实服务端关系清理，不清空无关普通聊天、资料、账户、模型、Skills 或无旧项目归属的模板定义；迟到执行和旧创建路径不能重建旧内容。桌面与实际 390px 下项目列表、创建、聊天、Sheet、上传和来源必须可经键盘/触屏访问，长名换行或可辨认、资料纵向滚动，页面不横溢出。JS DOM 交互检查不能代替实际布局证据。

## Orbit 组件设计语言（2026-10-22，当前视觉规范）

本节是对既有素白方向的统一精修，覆盖下节较早的颜色、字体、控件尺寸与圆角数值。保留工作区导航、页面密度及未被 SF-021 退役的业务行为和授权边界；不新增主题选择、业务保存或模型调用。

- **设计原则**：白色画布、墨黑主操作、连续灰阶、轻边界。页面以排版、对齐和留白分组；颜色只表达真实状态，一个操作组保留一个主操作。`/components` 是实际共享组件的展示入口，默认展示设计基础，其余页签保留可操作的控件、浮层、集合及动效。
- **字体**：按用户确认，全站界面、聊天正文及认证表单的中文、英文和数字统一使用本地 MiSans，正文 400、按钮/控件强调 500、标题及加粗正文 600；通过 `next/font/local` 加载小米官方原始 WOFF2 文件，使用 `display: swap`，按页面实际使用的字重请求并缓存，不依赖外部字体服务。`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC` 仅作加载期间或缺字回退；代码及编号保留系统 `ui-monospace` / SF Mono / Consolas；公开认证页也使用 MiSans，不再单独使用衬线标题。`--font-ui` 与 `--font-code` 分别映射到 Tailwind 的 sans/heading 与 mono。字阶为展示 32px、页面标题 24px、标题 18px、区块标题 15px、阅读正文 14px、控件/界面正文 13px、辅助信息 12px。手机输入保留 16px；中文正文行高 1.6–1.7，标题不拉宽字距。组件页同步展示 MiSans，使用帮助中标注字体来源并提供许可原文；原始文件不裁剪或改编。
- **中性色阶**：原始色板使用 `--orbit-neutral-*`：0 `#ffffff`、50 `#fafafa`、100 `#f5f5f5`、200 `#e5e5e5`、300 `#d4d4d4`、400 `#a3a3a3`、500 `#737373`、600 `#525252`、700 `#404040`、800 `#262626`、900 `#171717`、950 `#0a0a0a`。语义映射为 0 画布/表面、50 安静背景、100 次级/悬停表面、200 分割线、300 字段边界、500 焦点、600 辅助文字、800 正文、900 主操作。浅色阶是表面或边界，不作为白底的小字颜色。
- **语义色阶**：成功/信息/提醒/错误各提供 50、100、300、600、800 五级原始色板 `--orbit-{success|info|warning|error}-*`。浅色模式状态表面用 50、文字用 800、危险动作用 error-600；深色模式使用相容深底与 300 级文字。Badge、Alert、FeedbackMessage 共用 `success/info/warning/error` 及其 foreground token；图标和具体文案同时表达状态。色板本身始终展示原始值，深色模式只更换语义映射。
- **控件语法**：标准按钮、Input、SearchInput 与 NativeSelect 高 40px，小号 32px，大号/触屏至少 44px；Textarea 保留最小 80px。控件圆角 8px，小控件 6px，标签 4px，Card/Dialog/AlertDialog 12px。Checkbox/Radio 为 18px；Switch 默认 36×20px、小号 28×16px，滑块与边界保持 2px 留白。键盘焦点统一为 2px 环，默认中性描边、状态字段保留错误关联与明确红色反馈。所有组件通过共享实现读取 token，不在展示页另造控件皮肤。
- **表面与动效**：静态 Card 不加投影，轻阴影只用于菜单、Popover 与 Dialog 等浮层；表格表头、行高、悬停及选中状态共用中性层级。保留按钮 120ms 的颜色/边界与 1px 按下反馈、开关滑动、浮层淡入及展开/收起。Disclosure 的共享面板在展开和收起前均使用 Base UI 测量的高度，进入/退出样式才设为 0，以 180ms 连续过渡，结束后再卸载；减少动态效果时直接到位。现有键盘操作、焦点回归、Portal 私有边界与表单草稿保护不受视觉调整影响。
- **展示页**：在字体样张、带 HEX 的完整灰阶、四组语义色阶及间距/形状样本中展示真实共享基础；桌面采用说明/实样两条对齐轴，窄屏纵向排列。页签在窄屏可横向浏览，页面主体不横溢出。标题样张采用平衡换行，正文样张在窄屏不留孤字。说明保留对象、用途和必要状态，移除重复口号与不必要的设计说明；本地交互范围放在页尾和真实反馈中。就近错误文字使用 `error-foreground`，字段错误边界继续使用 `destructive`，状态标签完整展示中性、信息、成功、提醒与错误。

## 全站落地（2026-10-22，当前实现）

用户要求将已确认的组件方案应用到整个 Web 项目。本节覆盖下文历史记录中的页面视觉例外；未被 SF-021 退役或替换的业务功能、授权、状态、持久化和人工确认要求继续沿用原规范。

- **覆盖范围**：首页与普通/协作聊天、Agents 列表及创建/编辑/详情、Skills 列表及版本、资料库/上传/入库/检索、个人项目侧栏/普通聊天/资料 Sheet、个人任务、保留的流程模板编辑/画布、账户/模型/向量连接、团队/成员/邀请、登录与注册均消费同一套视觉基础。真实空库、搜索无匹配、加载与失败保持各自业务语义，不为展示制造数据。
- **排版与输入**：页面标题沿用桌面 24px/手机 22px；内容标题 18px、区块标题 15px，使用共享字阶与 600 字重。阅读正文 14px、界面正文及桌面表单 13px；移除业务页面对共享 Input/Textarea/SearchInput 的 16px 常态覆盖，手机继续 16px。字段错误小字使用 `error-foreground`，输入错误边界及危险入口仍使用 `destructive`。
- **表面与形状**：标准控件 8px、小号控件 6px、Card/画布节点/预览面板及 Dialog 12px；集合行依靠对齐、留白和单条分隔线分组。静态卡片不加投影，浮层共用阴影。选中、失败、成功和停用状态使用同一组语义 token，React Flow 的框选与缩放控制也映射中性主题。
- **控件与浮层**：标准操作 40px、紧凑操作（含 xs）至少 32px、主要触屏操作至少 44px。Dialog/AlertDialog 在窄屏左右各至少留 16px，正文和操作区共用容器内边距；底部不加分隔线或独立底色。保留焦点返回、Escape、表单校验、关闭保护、画布缩放及未退役动作。
- **窄屏表单与画布**：Agent 创建弹窗在手机使用 16px 分组间距，保留完整说明、独立滚动内容与固定操作区；重复的步骤播报仅对辅助技术保留，步骤条与当前标题仍可见。流程编辑器首次以 0.85–1 倍聚焦当前工作节点，避免默认全图缩小造成文字难读；“适应全部节点”及只读预览仍展示全图，后续手动缩放范围与保存的节点坐标不变。
- **反馈与动效**：集合悬停/颜色反馈使用共享 120ms，内容/浮层/展开使用 180ms，保留减少动态效果设置。去除局部独立的 150ms 过渡及公开页面的弹跳、长位移；不增加业务等待时间。

- **校验不位移**：每个字段常驻一行 20px 的消息位（提示或错误都在位内出现），表单级失败在按钮下方常驻 20px 一行；因此空态、字段错误、凭据错误三种状态下标题、字段与主按钮的纵坐标逐像素一致，点击后按钮不会从指针下移走。字段错误走组件的错误边界并把消息转红，表单级错误用同一红色语义；页面把 `--destructive` 映射到品牌朱红，保证这一页只有一种红。空字段提示「请输入邮箱。」「请输入密码。」「请输入用户名。」（覆盖共享 schema 的长度提示），长度或格式错误只在已有输入时出现；首错字段仍自动获得焦点，失败保留输入。
- **状态与焦点**：字段错误就近显示并把下划线转为朱红；首错字段自动获得焦点；失败保留输入，服务端失败用 `role=alert` 播报，过期与更新提示用 `role=status`（过期用朱红、信息更新用墨黑，不把两者画成同一种错误）。提交期间字段整体降为不可用外观但保留输入，切换链接不可点，按钮显示「正在登录… / 正在创建…」和轨道环加载标记，不显示未确认的成功状态；宣传图标题句点同步放大表示处理中。
- **动效**：只做三处——首次进入时三行大字以遮罩上移依次登场，责任链从左画出、节点依次落点，朱红回线随后从产品一侧折回销售、箭头落点带一次 120ms 的回弹收束；表单侧先可读（标题约 0.1s、字段与主按钮约 0.4s 内到位），整体约 0.9s 完成且只在进入时播放；字段与按钮的悬停、聚焦、按下反馈沿用公共组件的 150ms 过渡；提交时按钮内加载图标旋转、标题句点放大。`prefers-reduced-motion: reduce` 时直接呈现终态，不延迟内容与操作。
- **响应式与可读性**：≥1000px 分栏；640–999px 单列，保留完整站内文案，压紧海报内边距、字号与表单节距；<640px 单列，海报收成顶部的短海报，每站改为短标签（客户原话 / 完整上下文 / 技术评估），轴名保留，输入在触屏下 44px 高、文字 16px，主按钮为公共组件 `lg`（44px）；<380px 允许回问标注降到 11px 并让副题自然换行。验收：390×844 首屏完整显示主按钮与「注册账户」切换链接，320×568 首屏露出第一根输入横线，999×800 首屏露出邮箱字段；1440×900、1280×720、1024×768、768×1024 下标题不撞行、责任链完整、表单与脚注不被裁切。
- **实现边界**：公开认证页的字段与主操作复用 `apps/web/components/ui` 的公共组件，不 fork、不复制其样式；`apps/web/components/auth-form.module.css` 只负责宣传图、两栏骨架、字段节奏、常驻消息行与入场动画。宣传图用 CSS 绘制，不引入图片、图标库或第三方动效库；不展示未实现的找回密码或邮箱验证入口，不在页面或 URL 中保留凭据。

## 历史：组件视觉重设计（2026-10-21）

本节落实用户提供的 Refactoring UI 规则图，覆盖下文历史条目中“未修改的官方默认外观”要求；其余业务、权限、私有 Portal 和交互验收保持有效。该记录为上一轮仅共享组件与 `/components` 的历史范围；当前全站实现与用户确认的侧栏约束见上文“全站素白极简统一”一节。

- 2026-10-21 第二轮配色采用“墨印”方向：纸、墨、朱砂。纸色提供 50–950 共 11 档暖中性色，朱砂提供 50–900 共 10 档，松绿与赭石各五档；墨承担正文与主操作，朱砂只作印记（焦点、页签指示、品牌点、危险强调、区块编号），完成状态用松、提醒用赭。由 `globals.css` 映射到 `background`、`foreground`、`primary`、`ring`、`muted`、`success`、`warning` 等语义变量，组件不独立硬编码配色。深色模式映射为暖墨底与暖白文字；普通小字保持至少 4.5:1 对比度（纸底正文 14.9:1、次要文字 5.4:1、朱砂 5.6:1、松 7.5:1、赭 5.2:1）。本轮先落地语义配色与组件页的色板展示；字体、圆角与动效随方向继续深化。
- 正文、次要说明、辅助文字主要通过字重与灰阶区分。组件页桌面标题 30px、手机 26px，区块标题 16px、控件文字 14px；字段在移动端保留 16px。辅助信息为 12–13px，不使用低对比度浅灰正文，也不通过放大图标制造重点。
- 页面、详情及弹窗标题上方不再展示 `KNOWLEDGE`、`AGENTS`、`SKILLS`、`YOUR ACCOUNT` 等英文装饰行及其附属图标，直接展示主标题和用途说明。产品名、功能名称与真实编号保持可读，编号使用中文标签。
- 默认 Button/Input/NativeSelect 高 40px，主要大按钮 44px，Textarea 最小高 88px；触屏按钮、输入与页签至少 44px。日期网格在极窄屏按可用宽度自适应（36–44px），保留方向键选择和清楚焦点，避免日历浮层超出视口。统一小圆角与 150ms 左右的色彩/阴影反馈，2px 可见焦点环；减少动态效果时关闭非必要过渡及动画。
- 同一操作组仅保留一个实底主操作；次操作用描边或浅底，辅助操作用文字。危险入口保持浅红低强调，在专用人工确认中显示明确的红色提交；组件页危险按钮同样先打开确认演示，不删除真实记录。
- 首页与普通聊天的输入框底部操作栏，助手选择器靠最左，使用共享 shadcn `DropdownMenu` 的默认弹层、单选项与选中标记；弹层使用既有账户私有 Portal。触发器在常态、点击和键盘聚焦时均无边框、光环和底色，文字与下拉图标间距为 4px，键盘聚焦以文字下划线提示，保留 44px 触控高度、方向键、Escape 关闭和焦点返回。选择助手只打开对应空白对话，由本人发送消息后才执行模型。发送或停止按钮靠最右，使用 44px 圆形，距输入框右侧与底部各 8px；外框圆角为 30px，与按钮弧线形成等距关系。窄屏保持相同顺序，保留原有选择、发送与停止行为。
- Badge 使用浅底深字，状态同时展示图标或文字，不依赖颜色；长状态允许换行。Card 默认内边距 24px、小号 16px，用轻边界与极轻阴影分组，避免每个内容块都重复套卡片或分割线。
- `/components` 最大外宽 1248px，内容无需填满可用屏幕；宽屏按“标题说明 / 示例”两列，窄屏纵排。组间 32–40px、示例内边距 20–28px、字段组 24px、标签到字段 10px，保持组间距大于组内距。

- 共享空态使用 `apps/web/components/ui/empty-state.tsx` 的 `EmptyState`，由调用方通过 props 传入图标、标题、说明、按钮文字/图标及点击事件，可设置按钮样式、禁用状态、按钮属性和标题层级。组件只负责展示，不判断业务是否为空或发起业务请求；项目列表、项目内无任务、资料库列表、Skills 列表、Agents 列表与组件页演示共用此组件。列表的真实空库、搜索无匹配、加载及错误仍由原页面分别判断；资料库“选择资料”保留原上传弹窗与关闭后焦点返回，Skills/Agents 保留顶部新建入口，不在空态中额外重复按钮。
- 共享搜索使用 `apps/web/components/ui/search-input.tsx` 的 `SearchInput`，统一 40px 高度（触屏至少44px）、小圆角、内置左侧16px图标和绿色焦点边界。受控 `value` / `onValueChange` 由调用方维护，支持原生标签、键盘事件、错误关联、ref、禁用与只读；`containerClassName` 控制外壳宽度，`className` 作用于输入框。输入类型统一为 `search`，不得再用含清除按钮的整体组件包裹在 `Label` 中；有可见标签时以 `htmlFor` 关联，无可见标签时传入准确 `aria-label`。
- 有文字时显示“清空搜索内容”按钮，点击仅回调空字符串并把焦点返回输入框，不提交表单；只读时隐藏，禁用时不可操作。隐藏浏览器自带清除装饰，避免双重按钮；右侧始终预留操作空间，加载示例以同尺寸图标和 `aria-busy` 表示，不引起文字位移。搜索框不自行去空白、防抖、请求服务或拦截 Escape，原页面的查询、分页复位和异步取消规则继续负责行为。项目/任务/模板/Skills/资料列表、项目看板、技能选择、同事/处理人查找、向量检索调试及组件页的搜索输入全部共用该组件。
- `/rag/search` 的查询文本同样使用 `SearchInput`，保留2000个Unicode字符校验、Top K、资料范围、错误关联及取消查询；输入和清空不请求服务商，仍由本人显式提交触发检索。检索进行中或向量连接不可用时，查询输入与清除操作均禁用。普通聊天输入及其提及/命令补全属于消息编辑，不作为独立搜索框替换。
- 390px 下组件示例、长状态及弹窗纵向可达；不依赖页面横向滚动。操作结果通过可关闭的 `role=status` 轻提示播报，移动提示避开底栏；浮层沿用既有账户与工作空间隔离。

## 聊天与任务消息编辑器

- 普通聊天与任务补充消息复用同一输入器，保留一体化输入外观；不显示常驻格式、文件/Skill、命令或预览工具栏，也不显示常驻操作说明，操作失败时就近简短说明。Markdown 原文正常输入/发送，`@` 添加文件和 `/` 命令仍按需显示候选；不存储或执行 HTML。

## SF-022 普通聊天的人工介入

本节记录 SF-022 主动提问与操作审批的交互要求；实际交付与未执行项以 `docs/specs/SF-022-human-in-the-loop/changes.md` 为准。无项目聊天、个人项目文件夹聊天和仍合法的持久来源使用同一普通聊天，不新增审批中心、Task 接手界面或旧项目面板。

- Agent 补充需求一次只询问一个必要信息点，不把多个问题合并进同一题、说明或选项。每次真实回答后结合全部既有答案重新判断，只在仍有必要缺口时再问下一题，信息充分后结束提问并继续工作，不机械收集固定清单。
- 页面只显示当前待答问题，完整问题、必要说明和可选建议紧接原底部输入框上方，不重复渲染“正在回答”摘要或额外答案输入框。长内容可在有界区域纵向阅读，读屏将当前问题关联输入框。已回答、取消、替代或失效的问题卡不再显示，其持久记录及答案不删除；审批及其真实结果仍可读。建议按钮仅填入或追加到既有草稿，不自动发送、运行模型或覆盖未发送文字。只有本人发送时才提交精确问题编号和版本；自然语言“确认”只是答案，不批准工具或对外发送。工具等待产生的已完成空 Agent 回复不显示气泡或“已停止生成”的假状态。
- 等待问题时保留“取消此问题”专用动作，取消后可在原底部开始新讨论。轮询发现另一问题时，已有答案草稿仍绑定原问题，禁止悄悄改投新题；显示变化提示，由本人核对当前题后明确将保留草稿用于当前问题。旧问题已结束时保留草稿，并由本人选择将其用于新讨论。
- 有影响操作在正文后显示服务端冻结的工具/版本、动作、实际目标、影响范围及完整业务参数，正文与参数允许任意长串换行。待处理时提供“批准本次操作”“拒绝”“取消等待”；底部新输入可修改要求并使原审批失效，普通输入不构成批准。读取、搜索和计算在原授权内自动执行，不因演示而弹出审批。
- 批准回执明确为“已批准，等待执行”，随后依据持久记录分别显示执行中、成功、失败或“结果不明，已停止自动重试”，不把人工决定保存当作实际操作成功。操作终态保留冻结预览及真实回执，不提供可复活旧请求的批准按钮。现有协作发送保持原草稿、完整预览和一次专用确认；当前被 SF-021 关闭的旧发送路径不会因为新增审批而重新开放。
- 决策提交期间同步互斥并禁用对应动作，失败先读取原请求的已保存结果，未能确定时保留同一动作编号重试。答案失败保留完整草稿及原问题身份；丢响应先核对保存状态，旧版本冲突不自动关联新题。401、账户或工作空间变化继续清除旧私有界面。
- 普通消息被后台接收后，即使传输已结束，只要服务端仍有执行中的请求就显示后台执行和停止入口，阻止重复发送；三秒串行读取实际持久结果与人工请求，页面隐藏暂停、回来恢复，查看等待不运行模型。暂时刷新失败保留上次状态并明确提示未能刷新，不能显示假空态或假成功。
- 桌面和 390px 均保留唯一底部输入框；问题、长正文、完整参数、建议及批准/拒绝/取消可通过键盘和触屏访问。状态有文字与读屏反馈，焦点可见，建议及主要处理动作至少 44px 高，中文输入法确认不触发发送。不存在的生产写入/删除工具不显示为可用能力；隔离测试工具只用于验证通用审批边界。
