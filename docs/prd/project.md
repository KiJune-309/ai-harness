# AI Agent 平台项目总体 PRD

状态：设计草案。适用范围：服务器部署的多用户 AI 聊天平台。本文是唯一的 L1 项目 PRD；模块行为由 L2 文档定义，单个操作由 L3 功能 PRD 定义。仓库目前只有目录与工程配置，本文不表示功能已经实现。

## 背景与目标

项目希望让用户在同一平台中进行 AI 对话，并逐步使用知识库和个人插件。首个建设重点是 Agent：它能持续对话、调用工具、记录执行过程，并允许用户上传自己的插件代码。由于用户代码在服务器上运行，每位用户的插件和服务实例必须隔离。

首期目标是完成一条可验证的路径：用户注册并登录，上传和查看个人插件，创建对话，Agent 调用该用户插件提供的工具，用户查看自己的对话。登录接口返回 access token，后续受保护请求携带该 token。知识库能力在后续阶段细化。

## 用户与使用场景

| 角色     | 需求                                            |
| -------- | ----------------------------------------------- |
| 普通用户 | 管理自己的账号、插件和对话，并获得 Agent 回复。 |
| 平台运维 | 配置模型路由、沙箱策略并观察平台运行状态。      |

典型场景：用户登录后上传一个插件包。平台保存该插件的不可变修订版；用户启用后，Agent 可以在该用户的沙箱中调用插件工具，并把调用结果纳入对话。用户再次打开页面时，可以看到自己的插件状态和对话列表。

## 产品范围与阶段

| 阶段     | 交付范围                                                                                                 | 完成标志                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 第一阶段 | 账号注册与登录、token 验证、个人信息、个人插件上传与列表、对话列表、Agent 模型与工具循环、个人沙箱隔离。 | 两名用户可并行使用各自插件；跨用户数据和服务不可见；对话与工具结果可恢复和追踪。 |
| 后续阶段 | 知识库上传、入库和检索，以及更丰富的插件管理能力。                                                       | 在相应模块 PRD 审定后另行确定。                                                  |

第一阶段暂不包含团队共享插件、插件市场、子 Agent 和用户插件热重载。用户上传插件与启用插件是两个独立操作；上传成功不会执行代码。

第一阶段按“身份与 token → 个人插件上传和列表 → 插件启用与个人沙箱 → Agent 工具闭环 → 对话读取与隔离验收”的顺序推进。当前 L3 文档覆盖已明确的六个用户操作；插件启用、Agent 对话回合等功能在进入实现前补充各自的 L3 PRD，并以本项目目标和已确认的技术设计为边界。

## 模块与依赖

| L2 模块 PRD                         | 职责                                       | 主要依赖                                   |
| ----------------------------------- | ------------------------------------------ | ------------------------------------------ |
| [身份与用户](./modules/identity.md) | 注册、登录、token 验证、当前用户信息。     | PostgreSQL 用户主记录；Redis 短期会话。    |
| [个人插件](./modules/plugins.md)    | 插件修订版上传、列表、启用状态和沙箱装载。 | 身份模块、对象存储、PostgreSQL、沙箱管理。 |
| [对话](./modules/conversations.md)  | 会话创建、列表、回合状态和事件读取。       | 身份模块、Agent 模块、PostgreSQL。         |
| [Agent 运行](./modules/agent.md)    | 模型循环、工具调用、事件持久化和取消恢复。 | 对话模块、模型服务、个人插件沙箱。         |

`apps/web` 通过公开契约调用 `apps/api`。API 先验证身份和工作空间权限，再把可信上下文交给 `packages/ai-runtime`。PostgreSQL 是用户、会话和插件元数据主记录；Redis 存短期状态；上传包放在对象存储。用户插件代码在独立沙箱中运行，不获得平台数据库连接或模型密钥。

## 成功标准

1. 用户可完成注册、登录和携带 token 的个人信息请求。
2. 用户 A 的插件及对话列表不包含用户 B 的内容；越权请求由后端拒绝。
3. 上传成功的插件包以不可变修订版保存，初始为未启用状态；上传失败不会留下可启用修订版。
4. Agent 能完成“用户消息 → 模型请求工具 → 个人沙箱执行 → 模型最终回复”，并记录可重放的事件。
5. 工具超时、沙箱中断和用户取消均有明确结果；结果未知且可能产生副作用的调用不会自动重试。

## 交付与评审规则

每个功能先审定 L3 PRD 的输入输出、异常和验收条件，再实现接口和页面。模块边界或数据所有权变化时，同步更新[项目协作说明](../../AGENTS.md)和相应 L2 PRD。第一阶段是否可发布，以跨用户隔离测试、Agent 闭环测试及各 L3 验收条件为准。
