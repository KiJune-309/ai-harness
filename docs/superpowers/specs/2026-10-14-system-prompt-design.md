# System Prompt 模块 Spec

## 1. 目标：为什么做

统一组装并注入系统提示词，让普通聊天、流式聊天和工具调用后的继续请求使用一致的指令，避免各调用方重复拼接或遗漏提示词。

第一版覆盖片段组装、变量替换和消息注入，参考 [DeepSeek Harness 的 system-prompt 模块](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/core/system-prompt)。

## 2. 规则：应该怎么表现

### 输入

- 组装接收片段列表和可选变量。每个片段包含名称、顺序、文本，可选择关闭变量替换；变量值为字符串。
- 注入接收完整提示词和对话历史，历史允许为空。
- 片段文本和变量值允许为空字符串，完整提示词不允许为空白。输入由服务端调用方提供，凭据不进入提示词。

### 行为

- 需要组装时调用 `buildSystemPrompt`；完整提示词通过 `injectSystemPrompt` 注入，随后将消息交给 `LLM.chat` 或 `LLM.stream`。
- 片段按顺序从小到大排列，同序按名称排列；忽略空白片段，用空行连接。`{{name}}` 只替换一次，不递归解析变量值；关闭替换时保留原文。
- 提示词注入为首条 system 消息；已有相同的首条 system 时不重复添加。更新提示词时，从原始历史重新构建请求，不累积旧指令。
- 每次调用使用独立输入。模块只负责组装和注入；模型协议转换归 LLM，工具执行归 tools，权限校验归 API。用户输入和工具结果不自动成为系统指令。

### 输出

- 组装返回完整的系统提示词字符串。
- 注入返回新的消息数组，首条为唯一的 system。原有对话和工具消息的内容、顺序及协议字段保持不变，输入不被修改。

### 异常

- 重复片段名称、无效变量值、缺失变量、错误模板或最终空白提示词时报错。
- 历史中存在不同内容、非首位或多条 system 时报告冲突。
- 调用方收到错误后终止本次模型请求，不发送部分结果。模型接口失败仍由 LLM 和调用方处理。

## 3. 验收：怎么证明做对了

1. 将顺序为 20 的“B”和顺序为 10 的“A”打乱传入，仍得到 `A\n\nB`；同序片段按名称稳定排列。
2. “使用{{language}}回答”配合 `language = 中文` 得到“使用中文回答”；缺失变量或错误模板会失败，关闭替换时保留原文。
3. 重复片段名称、无效变量值和最终空白提示词会失败，不生成可发送的部分结果。
4. 重复注入同一提示词后，只有一条首位 system；冲突时明确失败。更换提示词并从原始历史构建请求后，只包含新的提示词。
5. 注入前后的原始输入不变；对话和工具消息保持原内容及顺序。两个工作空间分别调用时，变量和提示词互不影响。
6. 使用模拟模型请求验证普通和流式调用：OpenAI 在 messages 中收到 system，Anthropic 在顶层 system 字段收到提示词。
