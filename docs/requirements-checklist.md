# 第一阶段需求清单

状态：设计草案。更新日期：2026-10-02。本文用于追踪第一阶段范围、需求来源与验收证据；具体交互以 [L1 项目 PRD](./prd/project.md) 和相应 L3 功能 PRD 为准。仓库目前仍是目录骨架，下表项目均未实现。

## 使用规则

- 优先级：P0 是第一阶段闭环和发布所必需；P1 是后续阶段候选，不进入第一阶段验收。
- 状态：`待细化` 表示功能 PRD 或契约尚不完整；`待实现` 表示需求已描述但没有实现；`已验收` 需要有可复现的测试或演示证据。
- 每项只在对应验收证据通过后改为 `已验收`。需求变化先改 PRD，再同步本清单与[技术方案](./technical-plan.md)。

## P0 约束与质量要求

| ID    | 要求                                                                                                     | 当前状态 | 验收证据                                                                   |
| ----- | -------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------- |
| Q-001 | API 从 token 确定可信用户身份，涉及工作空间时另做权限检查；所有数据查询限定用户及适用的工作空间。        | 待实现   | 伪造请求体、查询参数、模型输出或插件响应中的 `userId` 均不能改变访问范围。 |
| Q-002 | 每位用户的插件代码在独立工作负载和 Cordis 根上下文中执行，不获得平台数据库连接、模型密钥或容器管理权限。 | 待实现   | 两名用户运行同名工具且互不访问；一方沙箱故障不影响另一方。                 |
| Q-003 | 上传包放在对象存储，PostgreSQL 保存引用与摘要；会话事件以每会话单调序号追加，Redis 不作为会话事实来源。  | 待实现   | 对象和摘要一致；事件顺序可重放；上传事务失败有清理记录。                   |
| Q-004 | 用户代码运行受 CPU、内存、时间、文件系统和网络策略约束；工具输出进入模型前受大小和敏感信息过滤。         | 待实现   | 部署环境中的资源与网络限制测试通过；服务端响应和日志不泄露凭据。           |
| Q-005 | Web、API、runtime、db 与 contracts 遵守仓库依赖方向，配置通过环境变量提供。                              | 待实现   | 构建、lint、格式检查和跨包依赖检查通过；仓库无真实密钥。                   |

## 进入实现前需定稿

1. 为 R-006、R-007、R-008 和 R-010 补齐功能 PRD，包括输入输出、异常和验收条件。
2. 明确首个工作空间如何创建或选定，以及切换工作空间时的授权规则；目前已有列表和 Agent 需求依赖 `workspaceId`。
3. 固定账号标识规则、token 有效期与撤销方式、插件包清单格式和上传大小上限。
4. 选定用户代码隔离运行时及部署验收环境；技术方案中与具体运行时相关的细节在选型后锁定。
