## 背景与问题

用户明确要求完成登录、注册和账户管理，账户管理包括修改用户名、邮箱、密码，以及配置自己的LLM，暂只支持OpenAI兼容接口。当前Web用签名匿名cookie标识浏览器，API依赖可信Web转发用户与工作空间header，并不存在真实用户、密码和可撤销登录会话；现有模型列表及DeepSeek连接为服务端全局配置，个人无法管理自己的模型连接。

本轮延续用户已授权的SDD流程：产品经理写Spec，主开发者写Plan/Tasks并实现，评测agent代理阶段审查及验收，不重复向用户请求确认。本轮以账户闭环为目标，不额外开展Syncless功能轮巡。

## 目标

- 用户能够注册真实账户，以邮箱和密码登录，刷新与重开页面后保持有效会话，并主动登出。
- 用户能够修改显示名、登录邮箱及密码，敏感修改须验证当前密码并真正撤销旧会话。
- 用户能够管理个人OpenAI兼容模型连接，普通聊天、自定义Agent及任务通过现有Cordis实际使用该连接。
- 用户之间的业务数据、会话与模型凭据严格隔离，生产数据可持久恢复，界面不以匿名身份冒充已登录账户。

## 范围

### 范围内

- 注册、登录、登出、当前账户读取、受保护页面及会话失效处理。
- 用户名（显示名）、邮箱和密码修改，邮箱唯一约束及会话撤销。
- 个人模型连接的列表、创建、编辑、删除、设为默认、主动连通性测试；名称、Base URL、模型标识及只写API key。
- 个人模型进入Agent模型选择与Cordis执行路径，保留服务端DeepSeek连接兼容能力。
- 真实PostgreSQL持久化与显式开发memory模式、隔离和错误恢复、测试及浏览器验收。

### 范围外

- 邮件验证码、邮箱已验证标记、忘记密码/密码找回、第三方登录、双因素认证、管理员后台、销号、团队邀请及跨设备会话管理页面。
- 自动迁移或认领此前匿名cookie下的聊天、Agent、任务、项目及模板。
- Anthropic/Gemini等原生协议适配、模型自动发现、计费、余额、配额、自动切换或自动选择模型。
- 用户输入LLM连接后自动发送测试请求；未点击测试或明确执行聊天/任务不调用模型。

## 用户场景

1. 新用户输入显示名、邮箱、密码及确认密码注册，直接进入自己的工作台，随后登出，再以同一邮箱密码登录；旧匿名数据不会出现在新账户内。
2. 用户在账户设置修改显示名，刷新后仍保留。修改邮箱或密码时输入当前密码；成功后回到登录页，所有旧浏览器会话失效，使用新凭据重新登录。
3. 用户添加“我的推理模型”，填写OpenAI兼容Base URL、模型标识和key，保存后按需测试并设为默认。普通新聊天使用默认连接，自定义Agent可明确选中该模型。
4. 用户编辑个人连接的模型地址或key，看到变更影响后续调用的说明；已有Agent/任务保留同一个个人路由引用，下一次执行使用该路由的当前配置。删除连接后旧记录仍可读，引用该连接的执行明确提示配置已删除，不静默换用其他模型。

## 非功能约束

- 保持Web只依赖contracts、API授权后调用core、db不依赖应用。身份与账户权限由API验证，LLM凭据解析也在服务端，不交给浏览器或公开契约。
- 状态改变操作具有同源/CSRF防护与请求体边界；登录不能用任意返回地址跳转到外站。会话撤销和敏感资料更新不能留下部分成功状态。
- API key输入只在本次用户明确保存/测试所需生命周期内使用，不以React持久化、URL或浏览器存储保存；已保存key不回读，错误日志须去除provider原始秘密。
- HTTP(S)地址规范化、路径拼接、重定向及目标地址限制必须由Plan明确并测试，不能仅前端校验；默认连接变更和唯一邮箱需抵抗并发。
- 本轮有意改变“个人模型”的冻结含义：冻结稳定路由ID，后续路由编辑可改变实际provider model，UI需明说；原全局DeepSeek模型和其余Agent配置冻结语义保持。
- 真实PG进程重启及个人连接的真实DeepSeek调用均需实际证据，不用mock代替。测试位于模块tests且遵循标准多行函数注释约定。

## 依赖与假设

- **已确认需求：**登录、注册，修改用户名/邮箱/密码，配置个人OpenAI类型接口。用户原有阶段代理审查授权继续有效。
- **本轮默认选择：**邮箱密码为唯一登录方式；用户名是非唯一显示名；注册后直接登录；邮箱改动与密码改动撤销全部会话；无邮件服务就不声称邮箱已验证，也不展示无实现的找回入口。
