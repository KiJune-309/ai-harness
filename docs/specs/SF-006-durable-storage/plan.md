## 技术方案与理由

正常 API 只接受 PostgreSQL，删除 CHAT_STORE/allowMemory 的产品启用路径；memory 适配器仅供测试显式注入。复用账户、会话、模型、Agent、聊天、任务、项目、模板和启动幂等表及事务。

本地启动优先使用外部 DATABASE_URL，否则用 infra Compose 创建专属 PostgreSQL 17、loopback 端口和固定命名卷。私有数据库凭据、服务 token 和账户 key 保存在忽略的 .local（目录0700、文件0600），普通停止不删除卷。已有本地配置而 key 丢失时拒绝生成替代 key。数据库初始化失败即失败。

认证来源桶、邮箱失败桶进入共享 PG。原子计数及事务锁保证窗口/上限；邮箱验证在跨进程邮箱锁内检查、验证、记录失败，成功仅清邮箱桶。异常释放锁，数据库失败不得绕过。标识使用 HMAC，过期桶有界清理。进程内执行控制仍可保留。

## 模块、接口与数据流

- packages/db：正常 createChatStore 要求 DB；AccountStore 增加原子频控及邮箱验证串行接口；新增频控表，复用原共享池，所有业务仍按 scope 过滤。
- apps/api：删除 memory 启动路径，稳定 key 必填，使用持久频控，状态报告 postgres。测试显式注入 fake。
- scripts/infra：本地数据库配置、启动/停止和 dev 集成，外部配置优先，不输出连接串。
- apps/web/contracts：正常使用持久状态，不再显示重启丢失；失败保留草稿、不显示假成功。

## 数据、兼容与迁移影响

源码/构建前，通过一次性本机 inspector 读取旧进程8类业务 Map、频控桶及实际加密 key；私有快照写0600文件，不新增生产导出接口。先初始快照，最终切换时关闭 HTTP listener、等待执行结束、再次冻结导出，不调用会清空 Map 的应用 close。

事务导入项目专属库，保留 ID、scope、时间、密文、请求指纹及幂等关联；不同记录冲突立即回滚，绝不覆盖。逐表/关联及摘要校验后才停旧进程。失败保留快照和旧进程恢复能力，不认领匿名数据。

频控表为增量迁移；旧 CHAT_STORE=memory 不再启用业务存储；独立 API 缺 DB/key 拒启动。已有真实 token/key 保持。

## 风险与缓解

| 风险          | 影响           | 缓解                                               |
| ------------- | -------------- | -------------------------------------------------- |
| watcher 重启  | 内存丢失       | 源码/构建前快照，最终切换冻结复查                  |
| key 生成/丢失 | 密文不可用     | 保全实际 key、稳定私有文件、丢失拒启动、错误不覆盖 |
| 并发频控      | 绕过上限       | PG 原子桶及邮箱事务锁、双进程边界测试              |
| DB 故障/错库  | 假成功或丢数据 | 无 fallback、专属固定卷、外部URL优先、导入冲突回滚 |
