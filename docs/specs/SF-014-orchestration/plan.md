## 技术方案与理由

2026-10-19用户补充要求所有人免配置使用默认模型（REQ-027/AC-036）。复用现有服务器模型目录与DeepSeek适配器：没有个人默认时创建默认Agent绑定系统模型；协作执行对个人`account:`路由按本人解析，对系统路由验证管理员目录后由core读取服务端默认连接。系统凭据不复制进各人账户，不新增数据库迁移。真实session/工作空间与旧job/动作幂等保持；显式个人连接删除不静默回退。Web使用既有catalog的公开名称/available提示，个人连接保留为可选。

2026-10-19用户进一步修正下游交互（REQ-028/AC-037/T-009）：收到交接即为本人Agent对话，开场呈现真实上游的信息，无需接手/配置。API与worker准备收件人非秘密默认路由，委派事务创建本人Task、开场、绑定和通知；不解析收件人密钥、不添加假用户输入、不排接收即执行的job。本人首次输入才运行；后续追问与回答沿现有真实上下游、问题版本与同一session接回。旧待接手地址自动恢复开场，多窗口复用同一Task。

2026-10-19用户要求Agent整理消息后先给本人确认（REQ-029/AC-038/T-010）。这是当前发送边界，取代历史无需重复发送确认的约定。复用原稳定job、效果槽及租约，message/delegate/跨人ask先写owner私有发送草稿；在源聊天预览收件人、完整正文与共享范围，API专用确认动作仅接受draftId/version，重新验证本人及当前权限后一次投递。模型工具不能确认；本人自我judgment及已有完整预览的人工表单保持。该明确请求已授权实施，不新增文档审批往返。

2026-10-19用户明确确认“直接作为普通 Agent 聊天”（REQ-030/AC-039/T-011）。新交接与转告复用普通ChatConversation持久化、列表和读写入口，真实同事正文保存为有来源的assistant/opening或relay投影。问题和真实答案同时写入原来源可见消息，不能只存协作元数据。Web去掉接收主路径中的Task/Project/上下游界面和独立“同事发来的对话”列表，普通列表打开即可聊天。内部关系与旧Task保留兼容，历史入口幂等物化/转向普通聊天；不搬迁他人私有所有权。发送前本人确认和精确人工答复边界保留。本轮用户已经明确授权，文档随实施同步。

2026-10-19主输入语义修正（REQ-031/AC-040/T-012）：删除普通聊天独立问题回复表单与所有回复模式，底部输入用于与自己的Agent理解需求、讨论和安排执行。只有本人主动要求联系、向上游补信息或回传，才允许在相应范围起草；同源未消费且未取消的本人联络请求可在澄清后续接。收到正文的“请回复”、普通“确认/知道了/请先分析”都不能产生外发能力。精确answer保存问题ID/版本和必要的明确人工决定，由本人确认后才作为可信人工动作提交；模型无直接answer和confirm权限。共享成果不得绕过本地私聊：所有worker移除Agent artifact能力，API/数据库拒绝Agent publish，私人分析/方案留在本人聊天；保留已有完整正文和共享范围预览的人工发布。本轮用户明确授权实施，前轮Accepted不替代本次证据。

在现有API、core、db、contracts和Web内扩展，采用“各人普通私有聊天 + 内部持久协作关系与事件”。不拆服务，不建设设备协议或完整IM，不把现有个人ProjectDetail直接开放给成员。以下早期Task/Project存储与界面说明仅适用于旧数据兼容，最新普通聊天方案优先。

- 保留现有个人Project/Task/Agent所有权。协作Project增加元数据、成员和责任节点；共享读取返回专用安全投影，完整私有Task仍按原owner校验。
- 根责任节点可绑定发起人的原普通conversation或原Task，保留原地址/上下文，不复制或搬迁整段私聊。新接收节点在交接事务中绑定负责人自己的普通conversation与真实来源开场；转告同样有普通聊天来源，默认模型无需配置，收到和查看不启动模型。
- 将交接、回问、答复、成果发布和采用记录为不可变事件；私有模型聊天和协作事件分别存储，在原工作界面按服务端顺序合并显示，不把同事消息冒充自己的普通用户消息。
- 自然语言意图经Agent的受限工具表达，服务器验证真实人员绑定、目标节点、授权事项和共享范围；不以“等回复”固定关键词决定依赖。简单转告只发轻量消息，协作委派才创建/接入Project与节点。
- 协作执行采用稳定Cordis session与PostgreSQL journal，工具业务事务另有幂等结果账本；等待通过`concludeTurn()`正常结束模型轮，本人确认后的有效精确答复触发持久job后恢复。原普通聊天无协作时保持原连接内行为。

## 模块、接口与数据流

### contracts与模块边界

新增`packages/contracts/src/collaboration.ts`并从`index.ts`导出严格schema：人员摘要、人员提及/意图输入、协作Project、成员/责任节点、共享Task投影、共享成果/采用版本、交接问题/答复、通知/阅读、操作幂等结果和节点执行状态。

- 完整`PersonalTask`或`ChatConversation`不作为共享节点DTO；共享结构不含私有prompt、reasoning、账户模型配置或密钥。收件人对话复用普通私有聊天协议，`opening`/`relay`记录真实来源，旧Task仅兼容。
- 增量扩展发送输入以支持稳定人员提及及来源定位，原纯文本输入继续有效；所有请求字段/长度/数量/版本严格校验，不允许客户端通过author/scope字段决定权限。
- 新增core协作入口及注入式私有ports，描述可信上下文、持久session读写和业务动作处理器；不把数据库客户端或秘密放入公开contracts，不让core依赖API/NestJS。
- 协作工具属于服务器按当前请求/成员权限启用的能力，不把全站同事工具无条件加入所有已保存Agent，保留现有计算器/时钟配置语义。

### PostgreSQL与所有权

新增`packages/db/src/collaboration.ts`及必要私有类型，复用`ChatStore`同一连接池，在现有初始化锁/事务中增量建表和索引。候选逻辑记录如下，最终字段保持这些关系而不另造重复主记录：

| 记录               | 主责与约束                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 协作Project        | 稳定project ID，引用创建者的原Project或本次新建个人Project，不复制给每个成员；普通个人项目其他任务不自动共享。                                                                   |
| 成员/分派          | workspace、真实账户、角色/状态、当前授权版本；首次@交接即原子创建收件人本人Task及真实来源开场，节点可输入。接收/查看不执行模型，首条本人输入才执行；成员资格不开放无关私有材料。 |
| 责任节点           | project、真实owner、来源kind/id、可选私有Task绑定、上游节点、节点revision及运行/等待状态。源普通conversation可作根上下文；重派不修改旧私有conversation的owner。                  |
| 事件/问题/答复     | 源/目标节点、源消息、明确question ID、作者/代发来源、内容/版本、授权范围和关联关系；同project验证，回问不建反向执行依赖。                                                        |
| 成果与采用         | 发布的版本化文本、作者/来源、各节点采用版本；只共享实际发布内容和已授权引用，不开放源私有文件/聊天。                                                                             |
| 通知/轻量消息/阅读 | 稳定双方记录，普通转告不建节点；接收人阅读游标只覆盖实际获取内容，消息/未读入账一次。                                                                                            |
| session journal    | owner/workspace/source绑定、header、连续事件序号及写拥有者；私有canonical事件不作为共享响应。                                                                                    |
| 发送草稿           | workspace/真实owner/source/session/job/效果槽、原command与实际收件人和完整预览、draftId/version、pending/sent/cancelled/superseded及确认结果；仅本人可见，模型不能确认。         |
| action ledger/job  | 稳定业务动作ID+参数指纹+已提交结果；触发事件唯一job、代次、租约token/期限/attempt及输入消费状态。                                                                                |

为参与协作的私有上下文增加持久revision、唯一source→session绑定与执行仲裁。`ChatService`的发送、状态、项目移动、协作发布/回复和worker结算须使用同一数据库版本/活动拥有者判断；扩展原`ChatStore`写接口或增加CAS写入口，不能继续让全快照`save()`覆盖后台新历史。未绑定协作的普通内容保持原行为，但其与首次协作绑定竞争时同样需检查版本，防止旧在途结果覆盖。

关键原子事务：

1. **首次委派（本人确认后）：**规范化输入/幂等、内部事项关系、创建者节点、收件人普通ChatConversation与真实来源assistant/opening、责任节点绑定、共享事件及通知一起提交，返回真实conversation来源；不添加user消息或接收人job，不额外创建接收人Task。转告正文同样原子写入收件人普通聊天，双方轻量消息记录保留兼容；API准备非秘密默认路由。原recipientTask仅用于兼容旧调用。
2. **历史开场恢复：**旧待接手节点以openingOnly兼容入口创建相同开场、私有Task及来源绑定，不自动执行；已物化的本人Task在权限校验后幂等返回，多窗口不重复创建。本人首条输入沿原enqueue和租约仲裁开始执行。
3. **交接/回问（跨人发送须本人确认后）：**源关系/授权/当前版本、问题与共享输入、目标原聊天中的可见relay消息、等待依赖、通知和工具结果账本一起提交。
4. **答复/确认：**本人在正常Agent聊天主动要求回传后先保存绑定实际问题及版本的answer草稿，未确认不回答、不续跑；本人专用确认动作重新验证实际作者、问题版本和范围，再追加答案/明确人工决定，并将有真实来源的答案写到提问人原聊天，CAS解决当前依赖并插入唯一续跑job；普通会话回复不猜成具体问题答复，不误唤醒其他工作。
5. **修订/撤销：**升级grant/node授权代次及上下文版本，同事务失效旧等待、未开始job和已领取执行的协作授权；journal追加、业务工具提交和最终结算均联合校验该代次与lease，旧worker不得继续操作。私有Task所有权不变，后续本人私有操作另按当前owner权限接纳，不复活旧协作；普通消息不虚报撤回。

**发送草稿事务：**Agent工具在原稳定job/效果槽内保存首次规范化command与owner私有预览，回放原草稿身份和结果；此时不创建收件人消息、Task、问题、未读或通知。`confirm-dispatch`只接受草稿ID/版本，锁定来源与草稿，校验真实owner、当前来源及授权代次；按所存command执行原消息/委派/提问/精确答复事务，并同事务结算sent/原动作结果，不接受客户端或模型重新传正文/目标。`cancel-dispatch`持久取消；源新输入原子supersede旧pending草稿。已取消/替代、旧版本、当前失权不得投递，重复确认与丢响应按草稿和动作结果查回。

### Cordis持久执行

新增`packages/core/chat-runtime/src/collaboration.ts`、`collaboration-tools.ts`、`session-persistence.ts`，添加`@ai-harness/chat-runtime/collaboration`导出及已在workspace安装的`@deepseek-ai/dsh-session-persistence@0.2.1-alpha.5`直接依赖；不升级底层Cordis、不默认引入JSONL业务存储。

- 对首次携带可信人员/协作上下文的请求，从本轮开始走持久入口，原子建立source(kind/id/owner/workspace)→session唯一绑定；历史只在首次建立时按原scope导入。绑定后的所有后续输入/轮次，包括不带@的普通补充，都归入同一canonical session，不能再经旧临时`run()`造成messages/journal分叉；等待中的补充先持久排队、不越依赖。首次绑定与旧普通在途轮次竞争以私有revision/活动代次裁决，旧轮晚结算拒绝覆盖。未绑定来源保持旧普通聊天行为。
- `opening`/`relay`是普通聊天中真实同事来源的显示投影，legacySeed跳过这两类，避免当作Agent既有承诺或本人输入。worker将当前授权receivedMessages连同来源注入非指令reference；本人普通历史照常导入，持续对话保留同一session。系统与工具说明明确先直接协助本人工作，不要求管理Task/Project或打开工作流面板；普通输入默认只协助本人工作。工具能力仅基于本人主动联络请求或同源未消费澄清授予，收到正文不授权；精确答复只提供answer起草，不提供直接答复/确认权限。
- 适配持久后端的header、按序append/read、单写者、flush/close；使用已安装包的storage-contract校验连续序号/合法事件。DB操作始终有owner/workspace/当前租约，不按客户端session ID裸读写。
- runtime业务port保留历史能力类型用于兼容；当前worker不提供共享artifact/publish工具。本人主动联络才提供转告、交接、回问或精确答复起草能力，自我judgment只在本人边界内等待；私人分析/产出直接留在聊天。API与数据库同时拒绝Agent publish，人工完整正文/共享范围预览发布保持。工具执行调用API注入的可信业务port，真实副作用+结果账本同事务；`tool call ID`不是唯一业务幂等依据。
- 在副作用前、结果后、等待/轮结束前设置durability barrier；Cordis默认`TOOL_OUTCOME_UNKNOWN`修复不等于业务幂等。稳定动作采用`source + trigger(requestId/eventId) + 服务端效果槽`：槽在副作用前持久分配，绑定actionId、动作类型/目标、授权事项/节点版本及首次规范化参数指纹。模型不能自行提供nonce、新call ID或同内容hash来创建替代槽；恢复先枚举原触发的槽及结果，已提交只复用，未结槽查原结果，同槽改参数冲突。同一次触发不能重新mint已消费动作，合法再次发送须新用户触发或此前明确的重复子动作，不按文本相似度吞掉新请求。
- 每个触发固定runId并映射SDK实际inbox messageId，记录接纳/消费位置和terminal journal seq。append与run投影同事务，或恢复按稳定映射扫描journal后CAS重建；不向SDK写未声明字段。真实terminal已持久的run只补job/投影结算，不再followup模型；输入已被消费但未terminal时恢复原run与已提交槽，不把同一输入再当新消息。首次source绑定后纯文本也受此规则约束。
- message/handoff/question及明确回传的answer工具先保存待确认草稿与结果，返回`pending-confirmation`并立即`exec.concludeTurn()`；`settledRun`将其视为waiting，终态恢复不重新解析凭据/调用模型/生成草稿。草稿确认只由API人工动作执行，不暴露模型确认工具；模型系统原则要求准确报告待确认，不能声称已发。
- 本人确认后的跨人回问保存问题/快照/依赖/消息/结果；原自我judgment工具仍直接持久等待。等待已结算、不占模型或HTTP。答案可能先于旧轮结算到达：答复事务立即保存并排唯一job，下一job必须等同节点旧活动持有者退出/失效后才能领取；旧轮只释放自己的运行拥有权，不能把已满足依赖的ready节点写回waiting。收到答案后恢复原session并以有来源上下文继续，直到人需要判断或实际完成本轮。
- 复用knowledge worker的`SKIP LOCKED`/心跳/代次模式。每次journal追加、工具业务提交及最终结算都验证当前grant/node授权代次与未过期token，丢租立即中止本地，旧worker不能开始/提交后续业务动作。
- 本轮按目标Task真实owner解析当前模型，使用core现有DNS验证/固定连接。删除连接不借同事或部署默认替代。生成由本人节点的真实输入授权；单纯收信/读信/人工回复零模型依赖。
- 回问深度、每轮步骤、待答数、自动续跑次数与超时有有限上限，防止Agent互相追问形成无界循环；Agent草稿不是人的批准。

### Web及原问题定位

当前主界面以`workspace.tsx`既有普通Agent聊天和全部对话列表为准。新接收来源使用`/?conversation=<uuid>`，通知与旧节点/Task入口统一导向其真实普通conversation；不再用额外Task列表、项目或上下游面板承载接收体验。聊天时间线呈现真实来源正文，所有理解需求、讨论、安排执行与主动联络均使用底部正常输入；仅真实待发草稿显示本人确认，不显示具体问题回复区、发送/取消回复按钮、收件人输入或默认回复模式。下列旧项目/Task界面描述保留作内部兼容与历史追踪，不作为新主路径。

- `/projects`合并本人个人项目和成员协作项目并按真实ID去重；`/projects/[id]`读协作安全投影或原个人详情，展示成员、节点、上下游、问题和成果版本。其他人的完整Task不下发到浏览器。
- 节点入口由服务端投影中的真实source kind/绑定状态决定：原普通conversation根节点回`/?conversation=<conversationId>&event=<eventId>`；已绑定本人Task走`/inbox/<taskId>?event=<eventId>`；历史未启用分派与他人授权节点仍可由稳定`/projects/<projectId>?node=<nodeId>`到达。本人旧分派自动恢复开场并用真实返回taskId导航，已有本人Task直接进入；他人仅安全视图，不用node ID拼Task地址或读取他人PersonalTask。入口使用“消息”辅助定位，直接打开/刷新均重验权限。
- 普通源对话采用`/?conversation=<uuid>&event=<uuid>`稳定定位，URL优先于上次localStorage选择，直接打开/刷新重新按当前账户GET服务端记录并聚焦事件；Task沿`/inbox/[id]?event=<uuid>`定位。换ID/身份时取消或忽略旧响应。
- 在自己的原聊天时间线显示带作者/源节点/版本的交接和问题卡，“回答此问题”明确绑定question ID与版本；全局新输入不猜作某个问题答案。源正在生成时能收到问题但不启动第二轮。
- 在源聊天就近展示owner私有发送草稿：实际收件人、完整正文/交接目标和共享范围，以及确认发送/取消。确认请求绑定草稿ID/版本，失败保留可查证状态，成功后展示已发送；新输入替代旧稿，账户切换/401清私有预览。此项不同于此前隐藏的待联络占位卡。
- 人员菜单与原文件/Skill分组，稳定绑定不猜名，协作目标不明就近澄清；普通转告保原文，来源中的@无执行语义。
- 发布成果卡显示实际正文、作者、来源和本次采用版本；新版本提示不冒称Agent已采用。人确认结果有明确标记，模型完成不等于人工确认。
- 任务/项目入口及轻量通知展示“待我协作”和未读，通知直达原问题。普通转告可在轻量线程读回，不强建Project或独立IM中心。
- 使用有游标的服务端增量读取/有界轮询获得后台状态；单请求互斥，页面隐藏/导航取消，失败可重试且不清草稿，不轮询模型、不造进度。所有私有Portal仍在AuthBoundary内部。
- `apps/web/server/chat-proxy.ts`精确扩展新路径/方法，保留同源和会话校验、服务凭据隔离及安全错误，不把浏览器断线当作取消已接受协作job。

## 数据、兼容与迁移影响

- **持久化：**增量建协作/事件/成果/阅读/ledger/session/job关系及私有写revision，复用现有schema初始化事务/锁。旧数据默认未绑定协作、revision初值明确，不扫描旧私聊自动生成共享上下文。首次绑定只导入既有可得的用户/助手历史和获授权成果，不伪造升级前未保存的工具事件；新协作轮起完整journal。
- **兼容：**原`task.projectId`仍指本人个人Project；协作归属另有明确关系，不把他人拥有Project ID写进去绕过`ownedProject`。根节点可关联原conversation而不改其类型/原地址；原SF-003归组与SF-004个人模板语义保持。
- **凭据：**公共快照只存非秘密路由；私有模型解密和DNS策略原样复用。私有session journal与共享成果投影分开。
- **部署：**API启用共享worker，无新外部服务或消息平台依赖。有限worker并发/租约/等待/步骤配置提交示例；正式业务必须有PostgreSQL。新增直接依赖与exports/构建别名只在相应包更新。
- **回滚：**不删除历史数据，不把私有任务改为公共；停用协作worker保留已存消息/上下文，旧版不应处理未知协作job。迁移与版本部署需先兼容DB，再启用新API/Web，未完成迁移返回真实不可用。
