## 背景与问题

用户要求接入 human-in-the-loop，并在本轮明确三项行为：首版同时覆盖 Agent 主动提问和操作前审批；问题展示在聊天中，答案仍通过底部聊天框提交；只对发送、写入、删除等操作审批，读取和计算自动执行。

现有协作发送已有持久草稿、完整正文预览及本人专用确认。Cordis 工具执行器也有审批入口，但应用尚未接通；上游即时审批服务仅支持同进程尚未结束的轮次。普通聊天当前主要保存文字历史，缺少通用的待回答请求、待审批操作及跨重启恢复语义。只增加问题或批准按钮，不能保证刷新后找回请求，也不能保证批准的是后来实际执行的内容。

当前生产可选工具主要为计算器和当前时间；项目资料查找、读取正在 SF-021 接入。它们属于只读能力。本期沿用已有发送确认作为真实发送场景，不新增写入、删除或外部设备工具来演示审批。

## 目标

- Agent 缺信息或需要本人判断时，可以在原聊天提出明确问题，等待本人通过原输入框回答后继续原工作。
- 具有发送、修改、删除业务内容等影响的工具操作，必须在执行前展示实际内容，由本人明确批准或拒绝；已获授权的读取和计算无需审批。
- 等待与人工决定持久保存，关闭页面、断线或服务重启后仍能处理同一请求，不靠模型重新生成问题或操作来恢复。
- 明确区分批准、实际执行和执行结果；重复提交、并发处理或故障恢复不能无依据重复操作。

## 范围

### 范围内

- 本人当前 Workspace 内的普通 Agent 聊天，包括无项目聊天、新个人项目文件夹内聊天及仍可用的已绑定持久来源。
- Agent 向本人提问、可选的单选建议、底部输入框回答、取消等待与同一工作上下文恢复。
- 服务端强制的操作分类、精确操作预览、一次批准、拒绝、取消与结果反馈。
- 已有协作发送草稿与专用确认的兼容；具备完整实际正文及共享范围预览的同一次发送不增加第二次审批。
- PostgreSQL 请求与决定主记录、权限和版本仲裁、恢复幂等、真实状态读取及桌面/手机交互。
- 通用审批阻断及恢复能力的验证；不存在的写入、删除工具仅作为明确标注的隔离测试能力验证该边界。

### 范围外

- 每个工具都审批、按 Agent 新增“自动/审批”设置、永久批准或一次批准后续任意操作。
- 新增文件写入、删除、命令执行、浏览器控制、支付、外部 IM 或设备工具，以及尚未具备的第三方插件执行能力。
- 将聊天中的自然语言“确认”“同意”解释为工具批准、发送确认或其他人的授权。
- 新建审批中心、多人审批链、外部通知、代理批准、自动催办或定时替人作答。
- 重新引入旧共享项目、Task 接手界面、上下游问答表单或公开本人问题及操作预览。

## 用户场景

1. 用户请 Agent 编写方案，Agent 需要明确目标读者，在聊天中展示问题和建议选项。用户点击建议仅填入底部输入框，或直接输入自己的答案，再按原发送动作提交；Agent 接着原工作继续。
2. Agent 等待本人选择方案时，用户关闭页面并重启服务。重新打开仍显示同一个待回答问题；查看不运行模型，回答才继续。
3. 用户让 Agent 计算或查阅本项目资料，已授权的只读工具直接使用，不出现批准弹层或等待状态。
4. 用户明确要求向同事发送内容，Agent 按已有规则展示真实收件人、完整正文及共享范围。本人确认后一次投递，不再重复询问通用批准。
5. 对需要审批的操作，本人拒绝后操作不执行；Agent 可以说明拒绝结果，但不能换工具或调用标识绕过相同的审批边界。
6. 等待审批时，用户通过底部输入框修改要求。旧请求失效，新指令按正常聊天处理；另一标签页后来点击旧批准不能执行旧操作。

## 交互约定

### 主动提问

- 问题位于当前聊天的相关 Agent 产出之后，展示完整问题、必要的简短说明、可选建议及真实等待状态。
- 保留原底部聊天输入框，不增加问题专属输入框或独立答复表单。待回答期间，输入框明确标识正在回答哪一个问题；提交绑定该请求及版本。
- 建议选项不是批准按钮，点击仅辅助填写答案，不自动提交、续跑或丢弃已有未发送文字。允许直接输入非选项答案。
- 本人可取消等待。取消后原问题保持可读及已取消状态；开始另一项讨论须先取消原等待，避免普通输入被悄悄归入另一请求。

### 操作审批

- 当前工具操作在聊天中展示工具/动作名称、真实目标、影响范围及完整业务参数或正文；不得仅展示模型生成的摘要和理由。
- 使用明确的“批准本次操作”“拒绝”动作；已有协作发送沿用“确认发送”“暂不发送”及原草稿身份。
- 等待审批时，底部聊天框仍可提交修改要求，该输入原子替代旧待审批请求。普通文字不批准操作。
- 批准成功只表示人工决定已保存；后续分别显示执行中、成功、失败或结果不明，不能提前显示已经发送、写入或删除。

## 非功能约束

- 遵守 AGENTS.md 的包依赖、真实账户/Workspace 授权、PostgreSQL 主记录、凭据保密及 Cordis 执行边界；API 承担人工动作验证，模型与 Skills 不产生人工权力。
- 等待不保持长事务、执行租约或活跃模型请求；进程退出不能清除有效请求，数据库故障不能降级为内存继续业务执行。
- 工具预览不展示 API Key、加密数据或其他秘密；授权读取不因“自动执行”变成任意路径、外链或跨范围访问。
- 沿用现有消息长度与有界工具执行；提问和审批不通过无限重试或模型空转推进。
- 实施遵守多行函数注释、测试目录、格式、lint、类型及生产构建约定；实际验证范围在 changes.md 逐项记录。
