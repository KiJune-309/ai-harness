## 技术方案与理由

用户在审阅需求稿后明确“开始执行”，确认需求并授权本轮完整实施。复用普通聊天与资料处理管线，新建独立的私人 project-folders 存储，避免把旧协作兼容壳当成文件夹。按现有 Cordis ToolRuntime 为当前项目提供只读资料查找与读片能力；采用数据库范围内的有界文本查找，不要求额外 embedding 凭据，不改变已有独立向量功能。

## 模块、接口与数据流

- contracts 新增 ProjectFolder/CreateProjectFolder；普通 ChatConversation/createConversation 增加 projectFolderId 和持久创建动作 requestId；KnowledgeDocument/上传/查询增加受校验的 projectFolderId。
- db 新增 project-folders 表与幂等创建，普通会话项目归属使用独立列且写入后不可被后续快照覆盖；文件关联保存 PostgreSQL，所有列表/读片/搜索在 SQL 中按 workspace/user/folder 过滤。
- API 提供 GET/POST /api/chat/project-folders 与 GET /api/chat/project-folders/:id；知识端点沿用原私有上传/处理/读片流程，解析并验证项目参数。普通会话创建原子验证文件夹与动作身份，首条消息沿用已有幂等发送。
- API 从真实会话解析项目，给 core 传只读资料端口；模型仅能查找关键词和读取本项目具体资料分片，不能提交用户、空间、项目或任意URL。注册非指令项目提示及来源链接格式；普通和持久会话使用相同能力。
- Web 在全部对话之前直接列可展开项目，提供新建项目与项目内新聊天；全部对话复用原会话集合。项目会话最右上角资料图标打开右侧 Sheet，列表/上传/处理状态与来源查看复用真实知识客户端。
- 旧项目页面不再可达，旧创建/成员/看板/资料发布以及会重新生成旧项目的交接/模板启动路径明确不可用。旧功能所需后台记录在启动 worker 前清理，避免迟到任务写回。

## 数据、兼容与迁移影响

新文件夹不从旧项目迁移。独立幂等清理按真实旧私人项目ID、Task当前/初始归属、协作节点精确source绑定收集关联会话，删除对应消息、Cordis journal及旧project aggregate业务内容、授权/任务/通知/动作记录。仅确有项目关联的资料内容副本及未被无关对象引用的物理资源进入清理；无关联知识库、账户、模型、Skills、模板定义保留。启动时串行schema/清理，且关闭旧写入路径；清理在 schema 初始化事务内持有表锁；当前开发热重载自动应用首轮迁移后，另加持久 v2 补偿动作账本清理，并在完整进程重启后复核。清理保持可重试，测试先用隔离schema验证保留集合。

## 风险与缓解

| 风险                           | 影响           | 缓解                                              |
| ------------------------------ | -------------- | ------------------------------------------------- |
| 旧Project兼容壳污染新侧栏      | 错误归属及共享 | 新独立模型，不复用旧listProjects                  |
| 快照覆盖新增归属或重试创建重复 | 会话串项目     | 独立不可变列、持久创建动作、范围验证与事务        |
| 资料跨项目召回                 | 私有正文泄露   | SQL直接范围过滤，工具闭包固定身份，严格参数schema |
| 仅隐藏旧数据或旧入口再生       | 旧功能复活     | 真实内容清理、旧写入口停用、worker启动前执行      |
| 清理波及无关内容               | 用户数据丢失   | 精确关系收集、共享资源引用检查、真实PG正反例      |
