## 背景与问题

用户明确纠正“项目”的产品含义：项目是本人创建的文件夹，收纳本人与 Agent 的普通对话和项目资料。现有项目主要组织旧 Task、协作成员、责任节点和看板，既不符合用户期望，也没有普通聊天与项目资料之间的真实关联。

本规格以本轮用户逐项回答为依据，重新定义面向用户的项目。SF-003、SF-016、SF-017、SF-020 中旧项目入口、归组、成员及进度界面的要求在本轮范围内被替代；保留历史规格作为开发记录，不据此迁移旧项目业务数据。

## 目标

- 用户能在侧栏直接展开自己的项目，找到其中的普通对话，在现有聊天界面继续交流。
- 用户能创建项目，并在项目里开始新的普通对话；所有对话仍可从“全部对话”访问。
- 项目聊天右上角提供资料入口，可查看本项目资料并上传文件；Agent 可按当前问题主动查阅本项目资料并据此回答。
- 删除旧项目功能及明确关联的数据，不把旧任务分组、共享项目或兼容记录当作新文件夹。

## 范围

### 范围内

- 当前真实账户、当前 Workspace 内由本人创建和拥有的个人项目。
- 侧栏项目名称、原文件夹图标、展开/收起、所属对话列表，以及创建项目和项目内新对话入口。
- 普通聊天的真实项目归属、项目内新对话、既有 Session/Agent/消息/输入器复用。
- 项目聊天右上角的资料图标、项目资料列表、上传及真实解析状态。
- Agent 根据当前问题按需查找和读取当前项目已完成解析的资料，回答使用资料时显示可辨认、可打开的来源。
- 旧项目 UI、旧项目业务记录、明确关联聊天和资料的删除，以及相关后台执行和旧链接的处理。
- 服务端授权、持久化、重启恢复、失败重试，以及桌面和手机交互验收。

### 范围外

- 把已有对话移入、移出项目或移动到另一项目；用户明确安排到后续。
- 新项目的团队成员、共享权限、项目看板、任务归组、上下游关系和工作进度管理。
- 项目嵌套、拖拽排序、项目级 Agent、跨对话记忆及自动合并多段聊天上下文。
- 新文件夹的删除、归档、批量管理，以及文件的共享发布、自动更新或外链抓取。
- 清空全部普通对话、资料库、账户、模型连接、Skills 或其他没有旧项目关联的数据。

## 用户场景

1. 用户创建“网站改版”和“客户方案”，侧栏在“全部对话”上方直接出现这两个名称与文件夹图标，没有额外的“项目”总折叠层。
2. 用户展开“网站改版”，选择其中一段对话；右侧打开原普通聊天，可继续输入、生成、停止和查看历史。
3. 用户在“网站改版”中新建对话，选择自己的 Agent 并发送首条消息；新会话归属于该项目，同时出现在“全部对话”。
4. 用户在该项目聊天右上角点击资料图标，看见本项目资料列表，并上传一份需求文档；处理完成后，用户问文档中的问题，Agent 主动查阅相关内容并说明来源。
5. “客户方案”中有同名但内容不同的文档；“网站改版”的 Agent 不得读取它，也不得读取未归入项目的个人资料。
6. 改版清理后，旧项目、旧任务归组/成员/看板和明确关联的聊天、资料不再存在；无关普通聊天和个人资料仍能使用。

## 非功能约束

- 保持 `web → contracts`、`api → core/db/contracts` 和 core 不依赖 NestJS 的包边界，不为此新建服务。
- 普通聊天的个人模型配置、冻结 Agent/Skills、持久 journal、版本/写租约及已授权的人工发送边界保持有效。
- 资料查询必须在数据访问时约束当前项目，不通过检索所有资料后在应用层过滤来实现隔离。
- 对长文使用有界查找和读取；上传完成解析即可按需查阅，不能要求用户另行配置聊天模型以外的凭据才能使用本期功能。是否使用向量能力由后续方案说明，不把已有向量调试等同于本期实现。
- 清理范围须有可复核的服务端关系依据；不以整库清空或删除所有普通聊天/资料表替代项目清理。
- 按仓库约定提供函数注释、测试位置、格式与 lint 检查，运行针对真实持久化、清理和资料执行的必要回归。

## 依赖与假设

- 当前个人项目存储、普通会话与资料处理管线可作为候选复用点；具体复用、替换与清理顺序在 Spec 通过后的 Plan 中确定。
- 当前普通会话及上传资料均没有独立项目字段；旧项目关联主要服务旧 Task 和 collaboration，不能直接等同于新项目归属。
- “打开资料列表”暂按聊天右侧面板设计，手机可使用可滚动浮层；不增加项目详情或进度页面。文件查询与回答来源的具体组件在实施方案中明确。
- 无项目的聊天不获得项目资料能力；加入同一项目不自动读取其他对话的完整历史。

## 未决问题

- 无未决需求；用户已于 2026-10-22 明确“开始执行”，本轮实施及 AC-001–012 的实际证据见 changes.md。
- 旧项目清理按精确持久关系实施，并以墓碑阻止迟到写回；没有旧项目关联的资料库原件不进入删除集合。
