## 技术方案与理由

直接消费同一安全progress完整快照，不建立Board主表、平行状态或新写入命令。服务器只派生精确来源存在性、本人输入事实及兼容Task真实完成事实；前端纯模型负责唯一归列、全量统计筛选和稳定排序，组件负责分批显示及精确导航。

## 模块、接口与数据流

- contracts：原CollaborationProgressNode增加sourceAvailable:boolean、started:boolean|null；严格白名单不增加来源ID、正文或私人Agent字段。
- db/API：原progress事务保留Workspace/Project真实权限；一次精确workspace/user/source ID/kind元数据查询，只在SQL内判断messages中role=user，assistant opening/relay不算。缺失/错kind为false/null；旧Task.started不作为替代。真实Task source.status=completed仅在安全读取投影中按历史完成处理，保留原撤权/取消优先、不写aggregate/新建状态，恢复Task后按真实现状投影。
- Web纯模型lib/project-board.ts：完整集合先唯一归列/计数，再按搜索/owner ID/待本人处理取交集，最后排序与渲染限额。真实合法wait统一入站/出站/self且self只一项，末端无效等待不复活；同人多工作各自保留。
- Web组件：TeamProjectOverview持有原唯一useProjectProgress；概览/看板切换与view=board链接，node/event深链先走旧授权页；成员/共享内容共同保留。筛选同项目保留、换范围清空；每列20项/每卡3等待逐批展开，统计始终来自完整集合。
- 状态/导航：按Spec顺序结束→来源异常/历史待激活→失败→运行→真实出站等待→未输入→可继续；不造完成率。只给本人精确ownHref/历史/原失败修复链接，其他人无源链接，所有操作只读或导航。
- 刷新：复用可见3秒串行轮询/隐藏暂停/abort旧请求；记录实际成功读取时间，暂时故障明确仅旧快照，401/403/404及范围变更清除数据和链接。

## 数据、兼容与迁移影响

无新业务表或状态迁移。原节点、wait、来源、Skills与普通chat不变；个人项目沿原四状态Task管理。扩展纯安全进度字段并同步精确白名单回归；兼容Task完成只读纠正现有投影，不能回写node或恢复已撤销grant。

## 风险与缓解

| 风险                            | 缓解                                                                   |
| ------------------------------- | ---------------------------------------------------------------------- |
| opening/收到relay被误认本人开始 | SQL只判断精确source持久user角色，错owner/kind与missing为未知           |
| Task完成与node旧状态不一致      | 读取真实Task completed事实，仅安全投影、不写状态；真实API完成/恢复验证 |
| ready/无等待被说成完成          | 明确六列优先级与历史完成标签，无比例/新完成命令                        |
| 先截断导致计数/过滤丢第21/41项  | 完整纯模型后切20项，41+数据与多条件回归                                |
| 同人多节点/多方向wait误合并     | node ID与真实from/target、self去重，target owner判待本人               |
| 切范围/失权仍展示旧链接         | abort旧请求、范围key与权限错误清快照，当前owner精确href验证            |
| 长卡/多列在手机溢出             | 390纵向六组，min-w-0/anywhere，实际键盘/展开/导航验证                  |
