## 背景与问题

SF-002 已实施真实个人任务，正在收尾验收。用户能够在独立任务中与 Agent 推进工作，但一个长期主题下的任务仍散落于任务列表，缺少真实项目入口、任务归组和整体进度。侧栏现有“产品与设计”“日常工作”分组来自界面演示，不能代表服务端项目能力。

用户已批准由产品经理与评测 agent 代为后续 SDD 阶段评审，主开发者写 Plan/Tasks 并继续轮巡。本规格是下一轮需求草案，仅准备文档；SF-002 Accepted 且本规格获授权代表审查通过后，才能进入本轮 Plan/Tasks 与实施。

## 目标

- 用户能够为一个长期主题创建真实个人项目，从明确入口重新找到它。
- 用户能够把多个现有真实任务归到项目，也能在项目中新建任务；进入后继续原有目标和 Agent 上下文。
- 用户能够在项目详情看到真实任务及四类工作状态数量，回到任务处理后再次查看时反映最新状态。
- 项目及任务归属遵循既有身份范围与真实存储策略，不改变 SF-002 的执行、完成恢复和幂等语义。

## 范围

### 范围内

- 真实项目入口、项目列表、按名称/说明搜索及稳定详情地址。
- 创建、编辑项目名称与说明；项目名称可重复，稳定标识区分项目。
- 每个任务至多归属一个项目，可加入、移动到另一项目或移出为未归组任务。
- 在项目详情选择既有任务归入，或复用真实任务创建流程在该项目下新建任务。
- 项目详情查看全部所属任务、各自状态、总数及四类状态计数；已完成任务也保留可访问链接。
- 任务详情显示当前项目归属并可返回项目；`/inbox` 继续包含当前身份的全部真实任务。
- 同身份/工作空间范围内的权限隔离、失败恢复、PostgreSQL 持久化及显式 memory 提示。

### 范围外

- 多成员邀请、共享权限、团队角色、任务转派、外部分享及真实账户系统。
- 项目模板、上下游连线、自动交接、任务依赖或定时触发。
- 项目文件与知识库、跨任务上下文共享、自动把项目说明注入 Agent，以及项目级统一 Agent 配置。
- 项目删除/归档、任务删除/复制、批量操作、拖拽看板、自定义状态、项目截止日期与独立项目状态机。
- 从普通聊天自动转换项目或任务，或迁移/保留演示项目作为真实用户数据。

## 用户场景

1. 用户创建“秋季产品调研”，填写说明，从项目页归入两个已有研究任务；下次从项目入口可直接找到这组工作。
2. 用户在项目中新建“比较定价方案”任务并选择自己的研究 Agent。保存后回到项目能看到一条未开始任务；只有进入任务并明确开始时才执行模型。
3. 用户从项目打开任务，补充信息并标记待补充或完成，再返回项目；计数和该任务状态反映保存结果。
4. 用户发现任务属于另一个主题，将其移动或移出；原来的目标、Agent 快照、状态和消息保持不变，原稳定任务地址仍可继续使用。
5. 用户打开另一个身份的项目地址或尝试把不属于自己的任务加入项目；系统不展示内容、不修改归属，也不泄露对方项目是否存在。

## 功能需求

| ID      | 需求                                                                                                                                                                                                                                                                   | 优先级 |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| REQ-001 | 提供真实项目入口与项目列表，替换演示项目分组，不自动创建示例项目。每个项目有稳定标识、名称、说明、创建/更新时间和稳定详情地址；列表按项目最近更新时间倒序，支持按名称或说明搜索。                                                                                      | Must   |
| REQ-002 | 可创建和编辑项目：名称去除首尾空白后为1–120个字符，说明去除首尾空白后为0–2000个字符；重复名称允许。创建使用同一动作标识重试返回原项目，同标识不同内容冲突拒绝；创建、编辑或归组本身不得调用模型。                                                                      | Must   |
| REQ-003 | 同一任务至多属于一个项目。用户可将当前范围内的既有任务归入项目、移动到另一项目、或移出为未归组；对同一目标重复提交是幂等操作，不复制任务或产生重复关联。已完成任务同样允许归组。                                                                                       | Must   |
| REQ-004 | 项目详情可新建真实任务，复用 SF-002 的名称、目标、Agent 选择和创建校验；创建成功时任务与项目归属同时可见。创建失败不能留下无归属的新任务或项目内半记录；项目不存在或无权访问时不创建任务。任务后来移动或移出后，重放旧创建请求只返回原任务当前记录，不重新应用旧归属。 | Must   |
| REQ-005 | 项目详情显示全部所属任务，任务行包含名称、当前工作状态、所用助手/模型和稳定任务链接，并显示总数及未开始、进行中、待补充、已完成四类数量；数量来自真实任务状态，空项目显示0项，不将空项目或一次模型结束视为项目完成。                                                   | Must   |
| REQ-006 | 归组不改变任务标识、名称、目标、实际 Agent 快照、开场消息、工作状态或历史；项目说明是管理信息，不自动成为模型上下文。不同任务的消息保持独立，SF-002 的完成只读、恢复、目标执行与重试规则继续生效。                                                                     | Must   |
| REQ-007 | 从项目进入任务后，详情可辨认当前项目并返回该项目；移动或移出后重新打开任务显示真实归属。`/inbox` 继续显示全部个人任务，已有任务直达地址保持兼容；任务状态变化后重新打开或返回项目能够读取最新行及计数。                                                                | Must   |
| REQ-008 | 生成回复期间禁止改变该任务的项目归属，界面不可提交且服务端明确拒绝；无生成时归组与任务状态/消息写入保持一致，并发移动最多保存一个归属，不能覆盖较新的目标、消息或状态。                                                                                                | Must   |
| REQ-009 | 项目及任务归属按既有用户/工作空间范围隔离；列表、读取、编辑、归组和项目内建任务均校验关联双方。外部身份的标识与不存在标识返回不泄露内容或存在性的响应，不改变任何已有数据。                                                                                            | Must   |
| REQ-010 | 项目信息与归属使用现有真实存储策略；PostgreSQL模式下API重启可恢复，显式memory模式同进程刷新可恢复且提示重启清空。列表/详情加载失败有重试，创建/编辑失败保留输入，归组失败保留原归属及计数，不以成功提示掩盖失败。                                                      | Must   |

## 非功能约束

- 保持现有DeepSeek Cordis执行机制和包依赖边界；项目管理由现有API及数据包承接，不为归组新建执行服务。
- 项目创建动作的原始规范化参数用于幂等判断；项目已改名后重放同一合法创建动作只读取当前项目，不回滚名称/说明。项目内建任务同样保留最初创建动作语义，重放不能撤销后续移动。
- 项目与任务关联以服务端真实数据为准；校验和写入之间的并发不能造成双重归属或丢失任务消息/状态，归组失败不能部分修改记录。
- 项目未完成/已完成任务数量是工作状态聚合，不是模型运行标志；本轮不增加项目完成状态或承诺团队工作流已实现。
- 保留签名cookie身份及现有权限边界，不将个人scope宣传为真实登录账户或多人共享项目。
- 遵循既有中性色界面与响应式交互；按钮、表单和选择器有可访问名称，错误可被感知，关键路径可键盘操作并在390px使用。
- 实施后执行相关契约/API/存储/客户端测试、浏览器验证、类型检查、构建、lint与格式检查；只将可复核实际证据记为PASS。

## 依赖与假设

- SF-002必须先完成独立验收且结论为Accepted；本轮不使用未验收任务能力掩盖前轮缺口。
- 项目归属不影响任务执行权限，加入/移出/移动均只允许当前可信用户/工作空间内双方操作。
- 正式持久化继续使用PostgreSQL；memory只能承诺同一API进程生命周期内数据保留，实际PG跨进程验证不能由mock替代。
- 公开一手文档足以支持本轮的个人项目概念；Syncless登录后页面仍未被确认为已实测，不臆造其布局和具体交互。
