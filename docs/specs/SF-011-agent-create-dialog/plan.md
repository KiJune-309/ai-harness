## 技术方案

1. 在现有 `AgentEditor` 内增加独立受控创建状态，区分“未选中/空态”和“正在创建”；新建按钮不再被空ID相等判断吞掉。初始只呈现真实列表/空态，选择已有Agent仍内联编辑，创建成功选择服务端返回的记录。
2. 将现有字段/配置预览组成单份编辑内容，只在创建Dialog或已有记录编辑位置之一挂载，保留名称、简介、稳定模型ID、prompt、tools、开场增删排序、验证/ref和原预览。使用现有共享默认Dialog，标题/说明、名称初始焦点和入口返回焦点明确；弹窗限定视口高度，内容区域纵向滚动，确认/取消及错误反馈在可达区域。
3. 创建仅提供明确“确定创建”与取消操作；确认通过同一共享schema校验后调用原 `createAgent(draft)`，有效返回前不变列表/数量。成功合并真实saved.id、更新baseline/选择、关闭创建并展示成功，零自动聊天。已有编辑继续 `updateAgent`，保存并聊天仍按submitter区分。
4. 新增同步提交ref互斥并配合saving UI；pending期间字段/确定/取消/关闭禁用，Esc/遮罩的关闭事件取消，不能以取消写入的方式隐藏结果。失败仍保留创建和全部草稿、字段首错与可见错误，允许重新确定，不承诺原POST未提供的持久幂等。
5. 关闭空创建直接清理；脏创建统一进入AlertDialog，继续编辑不清草稿，明确放弃后才清理关闭并返回新建入口。已有编辑脏稿切新建/记录沿原确认；若取消新建，原保存记录不被更新。嵌套确认正确恢复焦点。
6. 复用既有AuthBoundary/PrivatePortal与默认组件，不新建服务或依赖。用真实Editor包含实际Dialog/AlertDialog执行私有边界回归，故障保父草稿，401/身份变化卸载。UI规范补本轮新建交互，保留SF010及composer局部例外。
