## 背景与问题

用户要求在 `/agents` 点击“新建 Agent”后打开 shadcn Dialog，填写配置并点击确定，调用现有后端接口真正创建 Agent。当前页面默认显示内联新建表单；首次 `selectedId` 为 `null`，新建动作同样传 `null`，会被“与当前选中相同”的分支提前返回。入口没有明确的弹窗行为。

沿用已授权 SDD 代理审查，不再请求人工阶段确认。SF-010 的官方默认组件、私有 Portal、键盘与账户边界继续适用；本轮只调整 Agent 创建交互，保留现有持久化接口和已有 Agent 编辑功能。

## 目标

- 初始页面展示真实 Agent 列表与新建入口，创建表单仅在明确打开的 Dialog 内出现。
- 完整配置经现有共享校验和真实创建 API 保存；有效成功返回后才关闭弹窗、更新列表并选中新记录。
- 取消、未保存、校验、网络失败及处理中行为明确，不丢失未确认草稿、不并发重复提交、不自动调用模型。

## 范围

### 范围内

- `/agents` 的初始列表/空态、新建入口、完整创建 Dialog、确认/取消及相关错误/忙碌状态。
- 原有名称、简介、LLM 模型、system prompt、tools、opening messages（增删/排序）及配置预览能力。
- 创建后真实列表同步、已有 Agent 选择/编辑与未保存保护、适用回归和 UI 规范同步。

### 范围外

- 不新增 Agent 后端协议、数据库表、创建幂等字段、删除/复制/团队共享、模型连接配置或自动执行能力。
- 不把现有编辑器全部改成新的编辑产品；选择已有记录后的内联编辑/预览及“保存并开始对话”可保留。

## 用户场景

1. 用户进入空列表或已有记录列表，点击新建，填写名称、模型与能力，在弹窗内确定创建，看到已保存记录成为当前选中项。
2. 用户输入非法开场消息或收到服务失败，弹窗保留配置、指出问题，修正后可重试。
3. 用户取消未保存创建，选择继续填写或明确放弃；用户正在编辑已有 Agent 时，新建动作也先保护未保存编辑。

## 非功能约束

- 采用 SF-010 已建立的官方默认组件与安全 Portal，不引入另一套 primitives/定制皮肤；新增函数按AGENTS编写多行JSDoc。
- 创建字段不写入浏览器持久存储；既有服务端授权、公开模型路由和秘密边界不变。
- 现有 Agent POST 无持久幂等契约。本轮防重复限定同轮在途UI互斥，不承诺响应丢失后手动重试能达到服务端 exactly-once，不扩大后端范围或掩盖结果不确定性。

## 依赖与假设

- 现有目录、创建/更新API、共享Agent校验、PostgreSQL与SF-010组件可复用。
- 默认仍使用目录给出的模型及现有可用性规则；只创建配置，不在本轮验证连接或执行Agent。
- 继续采用用户已授权的产品经理/独立评测代理阶段审查。无须再次人工确认。
