## 背景与问题

用户要求完善现有资料库：“用户可以上传资料进行分片”“可以查看资料分片的情况”，并询问可以继续增加哪些能力。目前 `/rag` 只有硬编码示例，“添加资料”仅增加浏览器中的演示条目，未上传、解析或保存文件，也没有真实分片。需要交付真实、可恢复、按账户隔离的 RAG 入库基础，让用户确认文件是否被正确理解和切分。

沿用用户已授权的 SDD 协作方式：产品经理编写 Spec，主开发者编写 Plan/Tasks 并实现，评测 agent 代理阶段审查和验收，无需再次请求用户批准。代理审查仍须留下明确记录，未实际验证的能力不能标为通过。

2026-10-17 评测 agent 已代理批准本规格：范围与当前请求一致，格式和资源限额可验证，持久化、权限、作业中断恢复及分片溯源有明确验收标准。此批准允许编写 Plan/Tasks，不代表实现或任一验收标准已经通过。

## 目标

- 用户上传支持格式的文件后，系统真实提取正文并按可理解的参数分片，呈现可靠的处理结果。
- 用户可从真实资料列表进入详情，查看全部分片的顺序、正文、大小和来源，确认入库质量。
- 原始文件、资料元数据、处理状态与分片在刷新及服务重启后保留，失败可恢复，其他账户不可访问。
- 将后续检索与问答建议明确列为未来能力，不把“完成文本分片”描述为已完成向量检索或聊天知识引用。

## 范围

### 范围内

- 替换应用现有 `/rag` 演示列表，提供真实资料上传、文件名搜索、状态列表和稳定的资料详情入口。
- 单文件上传 TXT、MD、带文本层的 PDF 和 DOCX；原始字节保存在服务端私有对象存储，PostgreSQL 保存对象引用、资料记录、处理状态、参数、分片及幂等信息。
- 可配置按 Unicode 字符计数的分片大小与重叠，默认大小 1000、重叠 200。展示实际采用参数、提取字符数、分片数及逐片正文；准确标明“字符”而非 token。
- 解析/分片失败说明、失败重试、服务中断恢复、防止相同请求重试产生重复记录；提供授权下载原文件，便于核对来源。
- 账户/工作空间授权隔离、实际对象存储和 PostgreSQL 验证、浏览器桌面/移动与工程回归。

### 范围外

- 本轮不交付 embedding 模型配置、向量索引、混合检索、重排、召回调试、Agent/聊天自动检索、答案引用或知识问答效果承诺。
- 不支持扫描件 OCR、图片识别、音视频、网页抓取、压缩包、旧版 DOC、加密文档及宏执行；不得把没有文本层的 PDF 处理成可用资料。
- 不增加团队共享、知识库权限分组或个人项目绑定。这里“项目的资料库”指应用现有 `/rag`，仍按当前账户/工作空间隔离。
- 不交付资料删除/重命名、批量目录导入、在线分片编辑、已成功文件的重新分片版本管理、文件更新同步或大型文件后台集群。

## 用户场景

1. 用户上传自己的 Markdown 资料，调整分片参数，看到处理成功和分片总数，进入详情检查首尾分片及重叠内容，刷新后继续查看。
2. 用户上传带文本层的 PDF 或 DOCX，查看提取出的真实文本；扫描 PDF 或损坏文档显示明确失败原因，不显示虚假的零片成功。
3. 用户上传时遇到网络或服务中断，重试相同操作不会增加重复资料；处理失败可对已保存的原文件重试，不必再次选择文件。
4. 用户下载原文件核对上传来源；其他账户即使获知资料 ID 或对象 key 也不能下载原文、查看分片或重试。

## 非功能约束

- 遵守 AGENTS 的包依赖、持久化和权限边界；文档解析/分片留在 core，HTTP 授权/文件接收/任务协调由 API 承担，PostgreSQL 为主记录，原始文件进入对象存储。不得为本轮改写 DeepSeek Cordis 的 AgentLoop 或引入另一套聊天执行器。
- 文件解析必须有输入/展开后资源边界，不把恶意压缩 DOCX、超大正文或复杂 PDF 当无限制任务；不执行文件内程序，不因内容外链出网。公开失败信息不反射密钥、连接串或用户正文。
- 文件和分片按文本呈现，不执行 HTML；文件名不能作为对象路径授权依据，文件上传权限必须在处理前验证。
- 开发及正常运行必须使用真实持久对象服务与卷，不将对象内存 fake 作为正常回退；测试 fake 仅可显式依赖注入。

## 依赖与假设

- PostgreSQL、账户会话、工作空间范围、Web 服务端代理和持久本地配置已存在；资料库当前无真实服务，无历史真实文件需要迁移。既有演示条目不自动写入用户业务库。
- 单文件 10 MiB、正文 2,000,000 字符和默认 1000/200 是本轮有界初始产品取值，详情公开实际参数。后续调整需保持验证、文案与契约一致。
- PDF/DOCX 需采用可受限的实际解析依赖；扫描件 OCR 不在本轮。页码不是通用必需项，可靠字符位置是必须项。
- 对象服务可利用现有本地 Docker 能力创建专属持久卷；用户已配置的外部服务优先，不重置已有数据、不提交凭据。

## 未决问题

- 无需用户阻断性澄清。格式与限额、私有资料库范围及无 OCR 边界交由产品经理/评测代理按既有授权审查。

## 后续功能建议（未在本轮承诺）

1. **检索调试：**配置 embedding 模型，展示关键词/向量/混合召回的匹配分片、分数与来源，先验证“能找到对的资料”。
2. **对话引用：**让 Agent/聊天按授权选择资料库，回答附分片引用，可点击回看原段落，并区分没有依据和有引用的回答。
3. **质量治理：**已成功文件重新分片、分片预览与版本、重复文件提示、标题层级切分、扫描 PDF OCR，避免低质量内容进入索引。
4. **组织管理：**资料删除/重命名、标签、分组与个人项目关联，随后再加入团队共享和细粒度授权。
