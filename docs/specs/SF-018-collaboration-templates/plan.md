以下原计划已完成；本次只改任务模板页面入口及图形交互，依新增 REQ-013–REQ-015 / AC-019–AC-021 继续，原双类型 UI 与自研画布约定由修订方案覆盖。

## 技术方案与理由

保留个人模板完整契约与启动路径，在现有模块新增协作模板类型。复用PostgreSQL模板及collaboration主记录，以持久kind/同ID仲裁防旧接口覆盖。实例一次保存Project、逐节点普通聊天及真实来源；固定关系不成为调度器或外联授权。

## 模块、接口与数据流

- contracts：独立协作图/布局/人员/版本、完整服务器预览与启动结果；2–8节点单根连通无环，身份先规范化再校验。
- db/API模板：本人+Workspace范围，旧无kind作为personal；private与workflow读写/launch隔离且同ID不可转换。服务器生成实际开场全文，预览冻结版本/人员/共享范围/成员授权代次；确认同事务创建aggregate、每节点独立source、快照与幂等。非秘密模型metadata预备，不解密/执行；无Task/job/独立通知。
- db collaboration：固定实例目标和来源不可漂移，持久本人联络请求精确绑定source/target grants与问题version；新输入/取消/撤权失效。模型起草与本人确认均复验；既有target投递，禁止delegate复制或改写目标。
- 本人意图识别与worker：服务端保守识别明确自然表达，排除普通讨论/确认/引用，歧义只存待澄清且不开放能力。只读当前leased request生成固定slot，不信模型自报；同源澄清不能扩目标。普通非workflow路径保持。
- Web：同列表双类型、原个人编辑器保留，协作图独立组件；移动柄拖布局、显式upstream选择画边、处理人搜索、键盘/触屏等价。完整正文/范围预览后人工启动，冲突不丢布局与选中项。

## 数据、兼容与迁移影响

使用原包与应用，不新增服务或内存主记录。持久模板kind兼容旧private记录；launch与预览按kind及版本隔离，旧API不能覆盖workflow。实例冻结模板/原节点/布局/人员，只公开安全来源元数据，逐节点私人目标和source沿原授权。每次新启动全新节点/grants，重放只返回获授权既有结果。

## 风险与缓解

| 风险                           | 缓解                                                        |
| ------------------------------ | ----------------------------------------------------------- |
| 同ID跨类型覆盖或假404 fallback | 共享PK/事务kind guard；旧API与读取错误负例                  |
| 预览与实际opening/权限代次漂移 | 服务端完整预览快照+版本/人员代次校验，变化须重审            |
| 固定图变自动外联或复制node     | 持久本人请求/目标grant、无请求恶意tool负例、复用目标source  |
| 同人多节点串上下文             | 一节点一chat，按真实node消歧，不按人或首项匹配              |
| 拖动修改边/冲突丢布局          | 位置与边分离、草稿保留与显式重读、实际pointer/键盘验证      |
| 撤权重加后旧preview/草稿复活   | 成员代次、永久node fence、propose/confirm复验与真实竞争测试 |
