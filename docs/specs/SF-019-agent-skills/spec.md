## 背景与目标

用户要求依次建设团队协作的六项能力，SF-018 已独立验收，本项是第五项 Skills。现有 Agent 有系统提示词和工具选择，输入器也可把 SKILL.md 作为文本放进当次消息，但没有长期可复用、能维护版本的技能记录。用户无法将检查清单、输出规范或工作方法绑定到多个 Agent，并确认执行时用了哪一版。

本项提供本人在当前 Workspace 的私有技能库，将明确选中的技能版本绑定 Agent，由普通和协作两条 Cordis 路径实际使用冻结正文。技能提供方法和规则，不授予工具、脚本、对外联络或发布权限。

## 范围

### 范围内

- `/skills` 列表、创建、详情编辑、完整正文、不可变版本及历史查看。
- Agent 新建/编辑的技能多选、明确版本、全文查看、手动升级和移除绑定。
- API 解析合法私有版本形成 Agent 快照，新聊天/Task 的原有快照语义及两条 runtime 实际接入。
- 旧 Agent 无技能兼容、当前用户/空间隔离、持久化/幂等/并发和真实运行验收。

### 范围外

- 首版不做删除、归档或恢复；旧版本始终可读。后续若新增，须另定既有绑定和快照的兼容规则，不能偷偷清除旧技能。
- 团队共享技能、市场、外部技能安装/同步、目录资源包、脚本/代码执行、外链读取、插件或新工具权限。
- 默认自动使用整个技能库、按模型猜测自动挑技能、通用聊天临时切换技能，以及新增既有会话就地升级技能的入口。原有失败修复流程中，本人明确重选自己的 Agent 仍沿原规则采用该 Agent 完整冻结快照，不新增技能升级操作。
- 通过技能自动创建协作请求、批准、发送、发布共享成果，或在普通聊天增加协作面板。
- 第六项看板及设备能力。

## 功能位置与常见流程

### 技能库

- 在桌面侧栏和移动 Sheet 的“Agents”附近增加“Skills”入口，不增加移动底栏项数。页面沿用现有标题/说明、右侧“新建技能”、搜索/数量/刷新、Card 网格的样式，地址 `/skills`；说明“保存可复用的工作方法，再在 Agent 中选择具体版本”。
- 列表仅本人当前 Workspace，按更新时间倒序、稳定 ID 破同时间排序；搜索标题/说明，显示标题、说明、当前版本、更新时间及短编号。允许同名，通过编号辨认；数量不随搜索变动。区分加载、空库、无匹配和服务失败，不显示演示技能。
- “新建技能”打开默认 Dialog，依次填写标题（去首尾空白后 1–60 字）、说明（0–500 字）、Markdown 正文（去首尾空白后 1–16000 字，内部换行原样保留）。名称初始聚焦，正文区可滚动，底部取消/保存可达；有改动时关闭先确认放弃，失败保留输入。
- 创建成功进入稳定 `/skills/[id]`。详情按基本信息、完整技能正文、版本记录排列，使用同字段编辑；阅读保留 Markdown 原文和换行，不执行其中代码或链接。改动保存为新版本，历史按版本倒序可查看完整标题、说明、正文和时间，旧版本只读。
- 未保存修改或版本冲突时，明确继续编辑/放弃选择；重读最新版本保留本地正文供核对，不静默覆盖或自动再提交。没有删除/归档入口，避免破坏既有版本绑定。

### 在 Agent 中使用

- Agent 新建的第 2 步“行为与能力”，在系统提示词之后、工具之前增加“技能 Skills”区；已有详情/编辑也在相同位置。最多选择 5 个不同技能，所选正文合计最多 32000 字，区内显示已选数量及字符量。
- 从本人当前空间的真实技能中选择，默认加入所选技能的当前版本；每项显示标题、短编号、明确 `vN`，可查看该版完整正文或移除。绑定顺序为选择顺序，保存/快照/运行保持该顺序，不按标题或最新时间偷偷重排。
- 技能库已有新版时，对旧绑定显示“当前 v1，可更新到 v2”，由本人点击“使用新版”后再保存 Agent；不自动替换。修改 Agent 名称等无关字段仍保持原 v1。移除绑定同样保存后只影响随后新建的工作。
- Agent 最后一步确认预览及已保存详情显示绑定技能和版本，可阅读全文。说明“技能提供工作方法；工具权限仍由工具选择决定。库更新不会自动改变 Agent 或已有对话”。
- 创建/编辑/查看技能或绑定 Agent 不调用模型。使用入口是现有“保存并开始对话”、选择该 Agent 新建聊天或个人 Task；个人清单模板仍在启动时解析所选 Agent，连同技能快照冻结。通用助手和协作模板的默认助手不会自动套用创建者技能库。
- 原输入器“添加 Skill（SKILL.md）”改为明确的“添加 SKILL.md 文本（仅当前消息）”，保留原文本导入行为及边界，不冒充持久技能创建或 Agent 绑定。

## 版本、快照与私有边界

| 动作                                     | 应用规则                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------- |
| 技能库 v1 更新为 v2                      | 保存不可变新版本；绑定 v1 的 Agent 不变                                               |
| Agent 只改名称等字段                     | 原 skillId/version 和解析正文不变                                                     |
| 本人显式把 Agent 绑定改为 v2 并保存      | API 解析私有 v2，新建工作采用该 Agent 新快照                                          |
| 更新库或 Agent 后继续旧聊天/Task         | 始终使用原 Agent/技能快照，不回读最新库替换                                           |
| 本人在既有失败修复中明确重选自己的 Agent | 按原修复规则替换为该 Agent 完整冻结快照（含其技能），此后继续冻结；不因库更新自动触发 |
| 个人模板后续新启动                       | 按原规则解析当时 Agent；原实例不漂移                                                  |
| 聊天随后绑定协作来源/持久 session        | 继续用原本人技能快照，协作 runtime 同样生效                                           |
| 他人接收交接或协作模板开场               | 仍是其本人助手；不复制发送者技能正文或私有 Agent                                      |
| 切换工作空间/用户                        | 不读取另一范围的技能或绑定；共享项目不开放个人技能库                                  |

Skills 本期由本人维护、本人主动绑定。实际执行读取已冻结的 Skill 快照，不能在每次调用时拉最新技能，也不能把正文拼成代码、模板变量求值、网络抓取或工具注册。正文中的 `${...}` 等内容原样作为文本；它不改变既有应用策略和当前本人请求的优先级。

协作流程启动的默认助手不读取创建者或处理人的技能库。本期不为正常既有会话增加技能选择入口；在原有失败修复中，由真实本人通过既有公开重试操作明确选择自己的技能 Agent，才可按原规则采用其完整快照。该选择不改固定节点/来源、模板人员或联络权限，不能用数据库直接改写快照冒充本人选择。

技能名称/版本可在本人的 Agent/工作记录中显示；完整正文、私有技能 ID/快照不自动进入 Project 元信息、progress、安全关系投影、其他人开场、共享资料或公开模型目录。只有当用户以后明确审阅并确认发送某段正文时，才走原有人工共享规则，不能因技能写了“联系下游”就生成联络请求。

## 推荐数据与接口契约

这是供主 agent 规划的命名建议；字段与不变量须满足，内部组织可沿现有模块扩展，不新拆服务。

- 创建：`{ requestId, title, description, content }`；同动作/规范参数重试同一技能，异参数冲突。
- 更新：`{ version, title, description, content }`，基于已读当前版写新版本。重复提交同一更新动作不得重复升版；Plan 可补独立动作标识或等价的持久重放协议，不允许无界重复版本。
- `SkillRecord`：`{ id, version, title, description, content, createdAt, updatedAt }`；提供精确 `id/version` 读取和简要版本历史，全文均按本人/空间授权。列表可返回必要摘要，详情读取真实正文。
- `AgentInput.skillRefs`：`[{ skillId, version }]`，最多 5 个且 skillId 唯一，只接受引用，不允许客户端提交已解析正文冒充服务器结果。
- `AgentDefinition.skillSnapshots`：API 解析的 `[{ skillId, version, title, description, content }]`，有稳定顺序与合计限制；runtime 只使用这个冻结数组。旧 Agent/聊天/Task 未提供此字段按空数组兼容；没有技能时保留此前行为。
- 普通/协作 runtime 都把各技能作为有名称/版本边界、禁止插值的独立上下文加入该本人 Agent，工具注册仍只来自既有 `toolIds`，联络槽仍只来自服务端本人请求。快照不以覆盖原 systemPrompt 或扩充授权实现。

- 遵守现有包边界、PostgreSQL主记录、真实会话及双重范围，技能库/Agent绑定由API管理，core只消费已冻结合法内容，不依赖API/NestJS或每轮数据库技能查找。
