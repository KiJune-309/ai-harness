## 背景与问题

用户明确要求“前端所有组件都改成 shadcn ui，使用 shadcn ui 默认样式”，同时把 Sidebar 底部的更多、账户和退出操作合并到头像与用户名触发的 Dropdown Menu，桌面和移动导航采用同一模式。

当前 Web 由自制按钮、输入、select、原生 dialog/details、CSS modules 和全局控件主题构成；全局圆角、边框重置和焦点覆盖会影响新增组件。只安装依赖、只迁移组件展示页或给旧控件套上类似颜色不能满足全站迁移。需要让实际用户页面使用官方来源的 shadcn/ui 控件及默认主题，并保留已验收的真实账户、聊天、资料、向量、项目、任务和模板业务。

沿用已授权 SDD 流程：产品经理编写 Spec，主开发者写 Plan/Tasks 并实现，独立评测 agent 代理阶段审查和验收，无需再次人工确认。此文档不提前承认任何页面已经迁移。

## 目标

- 全部现有用户页面中有官方对应的界面控件都使用真实 shadcn/ui 组件，呈现统一官方默认样式。
- 桌面 Sidebar 和移动导航通过头像+用户名打开同一账户菜单，归并更多、账户设置和退出操作，保留现有可用入口。
- 页面表单、浮层、选择、折叠、反馈和组件展示具有正确语义、键盘、焦点和响应式行为，默认样式不被遗留 CSS 抵消。
- 既有后端协议、授权、凭据、数据和操作语义保持，尤其 Portal 浮层不能绕过账户复验与会话失效边界。

## 范围

### 范围内

- 按当前官方安装与 registry 来源引入适用于现有 Next.js 项目的 shadcn/ui 基础；使用统一默认主题和默认组件 variants，不继续复刻旧主题。
- 全部17个现有页面及共享 Workspace/AuthBoundary 的实际控件迁移，覆盖下表。
- Sidebar/移动 Sheet 与底部导航、头像 Dropdown Menu、原更多菜单中的组件展示/插件说明/帮助、账户设置和退出。
- 业务表单、确认框、Dialog/Sheet、Select/Native Select、复选/开关/单选、折叠、标签/卡片/表格/分页、反馈和加载等已有 UI 类型；迁移使用到的官方对应组件，不为了凑目录增加未使用能力。
- 收敛旧控件 CSS、更新组件展示与 UI 规范、交互/安全/响应式和生产构建验收。

### 范围外

- 不要求每个 `div`、`form`、段落、Next Link 或 Markdown 内 HTML 都替换为 UI 组件；业务布局、内容结构、Markdown 渲染和浏览器实际文件输入能力可以保留。
- 不新增页面业务、团队/插件后端、身份方式、模型/向量能力、主题切换器或定制品牌主题；官方目录中的未使用组件不要求全量安装。
- 不重写 API、数据库、Cordis、解析/向量策略、凭据存储或跨账户数据规则，不迁移/重算既有业务记录。

## 用户场景

1. 用户从登录、工作台进入资料库、Agent、项目与账户，按钮、输入、选择、浮层和反馈都使用同一默认组件体系，不出现新旧控件风格混杂。
2. 用户点击 Sidebar 底部头像和用户名，打开账户菜单，进入账户设置、组件展示、插件说明或帮助；菜单中选择退出，服务确认后才退出。
3. 用户在移动端打开导航 Sheet，再打开账户菜单；Esc、选择入口、返回和关闭正确衔接，不被重叠浮层困住，也不会因菜单在页面底部而无法使用。
4. 用户编辑模板或模型时遇到网络失败，原输入、动作标识和错误语义仍保留；账户复验或会话变化时，已打开的浮层与正文一起暂停或清除，不能继续操作旧账户。

## 非功能约束

- 遵守 Web 只依赖 contracts、服务端拥有凭据和授权的边界；UI库迁移不新增前端数据库/SDK调用或放宽模型网络策略。
- 新增/修改命名函数须多行 JSDoc，测试放各模块 tests；官方来源适配记录应能区分原始默认样式与必要项目变更。
- 最新明确要求覆盖此前控件视觉要求：旧全局主题、自制圆角/阴影/灰色画布或定制输入形状不作为必须保留样式。桌面导航布局、内容结构和已验收业务行为继续保留，冲突的历史 UI 规范须清楚标记被本轮替代。
- 不强加“所有 HTML 都必须是组件”或强迫更换 Markdown/文件解析；真正交互语义与授权边界不能因此豁免迁移。
