## 背景与问题

`packages/core/system-prompt/` 计划负责为模型请求构造系统级提示词，但当前目录尚未实现。现有 `packages/core/LLM` 接受调用方传入的消息列表，并将 provider 协议转换留在 LLM 模块；因此需要一个位于上层的独立模块，明确系统提示词的组成、注入位置与安全边界，避免提示词构造散落在请求调用代码中。

DeepSeek Chat Completions 支持 `system` 角色消息；其 JSON 输出需要在 system 或 user prompt 中显式要求 JSON。DeepSeek 文档还描述了基于重复输入前缀的上下文缓存，因此稳定的系统提示词可作为消息前缀，但缓存命中属于 provider 行为，不能由本模块保证。[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) [Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)

用户通过 `systemPrompt.context({ name, order, text })` 示例明确了需要保留的能力：调用方注册具名、有顺序的上下文片段，在构造系统提示词时通过 `text` 函数取得当前文本。本文将固定或按意图选择的指令称为“提示词正文”，将此接口注册的片段称为“context 片段”。最终系统提示词由选定正文与已注册的 context 片段组成；该接口需求以用户提供的示例为依据。

## 目标

- 为 core 调用方提供明确、可复用的 system prompt 选择与构造能力。
- Agent 配置了固定 system prompt 时，直接使用其正文并保留 context，不再运行 Laya 意图识别或追加意图提示词。
- Agent 没有固定 system prompt 时，使用 Laya 识别当前请求意图，选择相应的提示词正文并保留 context。
- 两条路径共用 context 注册与求值规则，确保提示词来源的选择或意图的变化不会跳过已注册的上下文片段。
- 让选定的 system prompt 位于对话消息前部，供现有 LLM 调用方传递给支持 system 消息的 provider，并尽量保持稳定前缀。

## 范围

### 范围内

- 根据 Agent 是否配置固定 system prompt，选择固定提示词路径或 Laya 意图识别路径。
- Agent 有固定提示词时，原样使用其正文，并在最终 system prompt 中保留 context。
- Agent 没有固定提示词时，基于 Laya 意图识别结果选择与意图对应的正文，并在最终 system prompt 中保留 context。
- 保留 `systemPrompt.context({ name, order, text })` 调用方式，支持具名片段注册、按 order 排序，以及在构造系统提示词时调用 text 获取当前文本。
- 构造供 core/LLM 使用的 system 消息或等价的系统提示词结果。
- 在动态提示词路径中，对相同意图稳定选择相同正文；context 可以随请求变化，正文与 context 的边界必须清晰。
- 对 JSON 输出等模式指令提供可组合能力，不承担 JSON 响应解析或 provider 参数设置。

### 范围外

- 调用 DeepSeek/OpenAI/Anthropic API，或变更 `packages/core/LLM` provider 协议。
- 执行工具、查询知识库、读取数据库或验证用户/工作空间权限。
- 管理提示词版本的持久化、后台编辑 UI、A/B 测试、模板市场或多租户配置存储。
- 承诺 DeepSeek 缓存命中、模型服从性、输出质量或安全策略效果。

## 用户场景

1. Agent 配置了固定 system prompt 时，聊天执行者采用其正文，求值并追加已注册的 context 片段，作为 system 消息传给 LLM，不调用 Laya，也不追加意图提示词。
2. Agent 没有配置固定 system prompt 时，聊天执行者调用 Laya 识别用户请求意图，选取相应正文，求值并追加已注册的 context 片段后传给 LLM。
3. 动态提示词需要 JSON 输出要求时，调用方可将格式指令纳入对应意图提示词；provider 参数和响应校验仍由调用方处理。
4. Laya 识别出的意图发生变化时，替换对应正文，已注册的 context 片段仍参与本次构造。
5. 调用方通过 `project:working-directory` 注册工作目录片段；每次构造系统提示词时，调用其 text 函数取得当前目录文本。

## context 注册契约

保留用户示例中的调用方式：

```ts
systemPrompt.context({
    name: 'project:working-directory',
    order: 100,
    /**
     * Returns the working directory text for this context fragment.
     * @returns The current working directory description.
     */
    text: () => '当前工作目录：/workspace/my-app',
})
```

| 字段    | 含义                                                                   |
| ------- | ---------------------------------------------------------------------- |
| `name`  | 当前提示词构造对象内唯一的片段标识，例如 `project:working-directory`。 |
| `order` | 片段的排序值，数值越小越靠前。只决定 context 片段之间的顺序。          |
| `text`  | 生成片段文本的函数；注册时不执行，构造系统提示词时才执行。             |

首版草案约定如下，作为待评审的接口行为：

- 固定或按意图选择的正文排在前面，context 片段按 `order` 升序追加；`order` 相同时保持注册顺序，片段间具有清晰边界。
- `name`、`order`、`text` 均为必填；同一构造对象内不允许重复 `name`。
- `text` 首版支持无参数、同步返回字符串的函数。每次成功构造时，每个注册的函数按片段顺序执行一次；下一次构造重新求值。
- 空字符串或纯空白返回值跳过该片段；未注册 context 时只输出选定正文。其他非空返回文本原样保留，包括内部换行。
- 回调抛错或返回非字符串时，本次构造明确失败，不输出部分提示词。错误可定位片段名称，不携带正文或 context 的原始内容。
- 异步回调、移除或替换已注册片段的接口不纳入本次规格。

例如，正文是“你是一个项目助手”，上述片段返回目录文本时，最终内容按以下顺序出现；标题和分隔符的具体形式留给实施计划确定：

```text
你是一个项目助手

当前工作目录：/workspace/my-app
```

## 非功能约束

- 必须遵循根目录 `AGENTS.md` 的包依赖方向、workspace 包边界与函数注释格式。
- 固定提示词正文不得受 Laya 结果或意图提示词配置影响；动态提示词路径根据意图结果选取正文；两条路径都保留 context。
- 确定性以 context 注册元数据、注册顺序及回调实际返回文本为条件；构造器不使用对象枚举顺序或自行生成的时间、随机值来排列片段。
- 不记录或输出提示词内容到日志；提示词可能含业务资料或敏感上下文。
- 任何默认系统提示词文本需要明确作为本应用自有行为维护，不得描述成 DeepSeek 官方提示词。

## 依赖与假设

- 现有 `@ai-harness/core` 负责模型执行，LLM 消息契约至少支持 `system` 角色的字符串内容；实现阶段需再次核对具体导出类型。
- DeepSeek 官方 API 是本次研究对象，用来确认 `system` 消息、JSON 提示词要求和前缀缓存行为；模块本身保持 provider 无关。
- 假设 Agent 配置由调用方提供；本规格中的“固定 system prompt”指 Agent 已配置且非空的提示词。
- 假设 Laya 是可由 core 调用方访问的意图识别能力；system-prompt 模块根据其返回的意图映射提示词，不负责身份或工作空间权限校验。
- 假设调用方已完成身份、工作空间权限校验，并仅传入允许用于本次模型请求的上下文。
- context 以用户提供的注册接口示例为依据；工作目录是回调返回文本的示例，本模块不新增专用工作目录字段或自动读取目录。
- context 回调由可信调用方提供，其数据准备、权限及副作用由调用方负责；本模块不提供回调沙箱。
- 首版的同步回调、排序同值处理、重名拒绝、空白省略与失败规则是本草案提出的具体约定，未将其标注为外部框架的已核实行为。
- 保留 context 注册能力不要求本模块管理持久化记忆；回调可返回调用方已获准提供的偏好或记忆文本。

## 未决问题

- Laya 识别失败或无匹配意图时，上层聊天流程应返回错误、请求澄清，还是回退到通用提示词？本规格要求不静默选择错误提示词，具体调用方行为待确认。
