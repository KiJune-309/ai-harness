## 背景与问题

用户要求接入“真实的向量数据库，和向量模型”，并询问向量模型如何配置；用户已选择 OpenAI 兼容的云服务。SF-007 已实现资料上传、真实解析、持久化分片及原文件下载，目前没有 embedding 配置、向量索引或语义召回。现有账户“模型连接”只服务聊天，不能把聊天模型、聊天 API key 或当前 DeepSeek 默认配置当成向量配置自动使用。

本轮建立独立的 embedding 连接配置，复用 PostgreSQL 并接入真实 pgvector，在用户明确操作后为现有资料分片建立向量索引，再用同一模型空间执行查询，提供可以查看原分片与来源的最小召回闭环。继续沿用已授权的 SDD 阶段代理评审，无需再次人工确认；不预先宣称实际云模型或任何 AC 已通过。

2026-10-18 独立评测 agent 已依据既有阶段代理授权批准本规格。独立配置、真实向量类型/余弦计算、模型版本与维度隔离、持久批次/租约恢复及零隐式外呼均可检验；真实云模型 AC-002、AC-011 仍须实际用户配置，不能用协议 fixture 代替。此批准仅允许进入 Plan/Tasks 阶段，不提前承认任何实现或验收通过。

## 目标

- 用户知道在何处填写 Base URL、API key 和 embedding 模型标识，实际测试后看到真实维度和服务返回的模型身份，不要求用户猜维度。
- 用户主动选择已完成分片的资料建立真实持久向量索引，看到处理结果、失败原因与可恢复操作。
- 用户输入查询，在真实 pgvector 中召回自己的相容索引，核对匹配原分片、来源和余弦距离，不能混入其他账户或其他模型空间。
- 本地数据库启用扩展并重建容器后，已有全部业务数据、原文件、资料分片及新向量索引均保留。

## 范围

### 范围内

- 账户中独立的 embedding 连接管理、主动连接测试、唯一默认选择；只适配 OpenAI 兼容 `/embeddings` 协议，云服务为本轮用户选择。
- 服务端加密保管只写密钥；名称、Base URL、model、版本、实际维度、已验证 provider model、默认与验证状态等安全元数据。
- PostgreSQL 的真实 pgvector 扩展与持久向量列，支持不同用户或模型连接具有不同维度，首版通过余弦距离精确查询建立可验证闭环。
- 对现有 ready 资料手动建立/重建索引、真实状态与进度、失败重试、批次持久化、幂等及中断恢复；不修改原分片正文。
- 资料库召回调试：输入查询、选择 Top K，查看真实匹配分片、文件名、序号、来源位置及余弦距离/相似度。
- 版本变化及模型空间不相容提示、权限隔离、有界模型调用、安全错误和真实重启/工程验收。

### 范围外

- Agent/普通聊天/任务自动使用资料库、答案生成或引用、重排、关键词混合检索、检索质量自动评分及 ANN 性能承诺。
- OCR、网页同步、资料删除/重新分片、团队共享、跨工作空间检索及外部独立向量数据库产品。
- 自动选择云服务商、替用户申请密钥、读取或复用聊天密钥、免费模型承诺、余额/费用估算、自动全库索引。
- 多模态 embedding、非 OpenAI 原生协议、手填输出维度或向 provider 发送 `dimensions` 参数。维度范围为实际测试所得的 1–4096，不悄悄降维、补零、截断向量或混合不同距离策略。

## 用户场景

1. 用户在账户的“向量模型”区域新增连接，填写 API 基础地址、embedding model 和 key；保存不发请求。点击“测试连接”后，系统用两条固定非秘密短文本实际访问服务，展示验证成功、实际维度与 provider 返回的 model，然后用该连接作为默认向量模型。
2. 用户在已完成分片的资料详情看到“尚未建立向量索引”。确认模型、维度和片数后点击开始，系统持久化任务并处理；上传或分片成功本身不自动产生 embedding 调用费用。
3. 用户在召回调试中输入问题，看到自己的 ready 分片按余弦距离排序，点击来源查看完整原文片段。没有相容索引时提示先建索引，不发无意义的查询 embedding 请求。
4. 用户修改连接地址、model 或 key，原索引显示需重新验证/重建，不能把新模型查询向量与旧模型向量混用。改连接名称不使有效索引失效；切换默认不会自动重建或自动扣费。
5. 服务中断或一批 embedding 失败后，已保存资料和分片仍可读；失败可手动重试，重启后任务按持久状态恢复，完整成功后才允许召回。

## 非功能约束

- 遵守现有包与权限边界：embedding 协议、向量化/查询编排稳定入口属于 core；API 拥有真实身份、模型授权、密钥解密和受信任上下文；PostgreSQL/pgvector 保存主记录/向量/作业；Web 只依赖公开 contracts。不得为 embedding 绕过 Cordis 或改写已有聊天执行路径。
- 不伪造不可得的 tokenizer、token 使用量、付费额度、索引进度或远程模型内部版本。冻结 verified provider model 和本地配置版本能检测声明身份/维度变化，不能证明提供商在同名、同维下从未修改权重；配置说明应建议使用稳定/带版本的 model 标识。
- 用户提交的 Base URL 由现有网络策略限制；所有 embedding 外呼均通过该策略，不能只在“测试”时校验地址而让后台或查询绕开。
- 长资料请求必须有界分批，失败不丢原始分片，不向 provider 发送不属于当前用户的数据。持久批次和内部幂等不等于第三方请求费用去重，不能承诺崩溃窗口零重复收费。
- 启用扩展须保持现有 PostgreSQL 主版本/平台与数据目录兼容，先保全再切换，不通过删卷解决安装问题；向量库不是新增匿名数据体系。
