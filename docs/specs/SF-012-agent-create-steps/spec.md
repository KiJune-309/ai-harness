## 背景与问题

用户希望以步骤方式填写新建 Agent。SF-011 已提供真实创建 Dialog，但全部字段一次展开，长提示词、工具和多条开场消息需要反复滚动。本轮将创建 Dialog 改成三个清晰步骤，仍由最后明确确认调用原创建 API。

沿用用户已授权的产品经理/评测代理审查，无需人工阶段确认。保留 SF-010 默认 shadcn 样式、SF-011 创建生命周期、现有方形 Agent 卡片与已有 Agent 内联编辑，不新增后端能力。

## 目标

- 按“基本信息→行为与工具→开场消息与确认”逐步完成同一份完整配置。
- 前进先检查当前步骤，返回不丢内容；最后明确确认前无创建请求或模型调用。
- 错误、失败、取消、处理中和身份复验仍保留正确草稿、当前步骤与焦点。

## 范围

### 范围内

- 仅 `/agents` 新建 Dialog 的步骤指示、字段分组、上一步/下一步、最终配置摘要和确定创建。
- 原全部配置与校验、跨步首错定位、草稿/焦点/忙碌/私有 Portal 兼容、现有测试及 UI 规范同步。

### 范围外

- 不修改创建/更新API、共享字段契约、数据库或模型/工具能力，不增加独立路由、持久创建幂等或云模型调用。
- 不改已有 Agent 的完整内联编辑/两种保存，不改当前方形卡片列表，不引入自定义 Stepper 库或另一个主题体系。

## 用户场景

1. 用户新建助手，先选名称与模型，再写角色并选工具，最后调整开场消息、核对完整配置并确认保存。
2. 用户返回修改前面的模型或提示词，再前进时其他内容和开场顺序仍在；非法字段只在应处理步骤指出。
3. 用户提交失败或取消后选择继续，仍处于原步骤且草稿完整；等待身份复验恢复后也能继续当前步骤。

| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| REQ-001 | 新建 Dialog 依次显示3步：①基本信息（名称、简介、LLM模型）；②行为与工具（system prompt、注册工具选择）；③开场消息与确认（最多5条开场消息的增删/排序、完整配置摘要）。清楚显示当前步/总步数与各步名称；新打开、明确放弃或成功后下一次新建均从第1步开始。步骤标题不提供绕过校验的自由跳转。                                                                                                          | Must   |
| REQ-002 | 上一步/下一步及步骤导航不会提交表单或请求服务；下一步仅校验当前步字段，非法时留本步、就近错误并聚焦首错，不提前要求未来步骤字段。上一步可直接返回并保留全部输入、工具与开场顺序，再前进使用同一草稿；导航后当前步内容可被键盘与辅助技术理解。非当前步不挂重复编辑字段/ID。                                                                                                                        | Must   |

## 非功能约束

- Web只依赖contracts；所有创建/权限/密钥及Cordis执行边界保持，前进/返回/摘要不调用模型。
- 不把步骤状态或未提交草稿写本地持久存储，不改变SF-011已确认的取消放弃与在途互斥规则。
- 新界面使用现有默认组件组合，不要求仓库中不存在的官方Step组件；具体组合、焦点调度和复用方式由Plan决定。

## 依赖与假设

- SF-011已验收的真实创建Dialog、既有卡片列表/编辑器、公共校验/客户端及私有Portal可复用。
- 各字段原默认值、长度、工具/开场上限及规范化规则保持；只更改创建时的呈现与前进校验时机。
- 用户已有全部阶段代理授权，产品经理/评测继续代理审查，无需人工阶段确认。
