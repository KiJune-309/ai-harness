## 技术方案

保留 splitKnowledgeText 接口、现有提取/规范化、字段、范围及默认值，无新依赖、数据库迁移或配置。core负责分片，db负责完整批次校验，Web仅同步参数含义。

一次扫描Unicode code points，建立五层有序数字边界数组：空白段落界、单行界、句末、子句标点、其他空白。组合标点及紧邻闭合引号/括号一起结束；ASCII数字间的点/逗号/冒号不注册为自然标点，普通英文点只在合理句末上下文注册，URL协议冒号不注册。所有字符保留原位置，不trim、重排或引入NLP。

每片上限为min(start+chunkSize,N)。余文能放下则直接收尾；否则逐层二分查找不超过上限、严格大于上一片end的最远边界，找不到才Unicode硬切。按源数组[start,end)截取，沿用PDF页区间相交计算。实际push前检查5000片上限，禁止旧固定overlap公式误拒合法批次。

重叠在[max(start+1,end-overlap),end)中逐层选择最早自然边界，完整尾单元优先且不重复整个前片；无可用自然边界则0，仅本片因无合适边界硬切时允许字符回退。下一片start和end都严格增加，结束候选须超过已覆盖end，防止纯重叠片/停滞。复杂度为一次线性扫描及每片有限次二分，内存为字符数组和五层数字位置数组，禁止每片重扫全文。

## 持久化与兼容

knowledge.complete移除非末片必须满长、固定start步进和固定重叠比较；改为验证真实Unicode长度/源范围/最大长度、连续序号、首0末N、相邻start/end严格增加、无洞、实际overlap在0..预算且小于前片长度，并按实际交集比较正文。保留document/owner/lease/token/attempt/CAS与整批事务/回滚，旧固定窗仍为合法特例。

旧ready文档、chunk、vector/job不写不迁移。新上传及未完成任务实际解析、显式失败重试/租约恢复采用新函数；不承诺跨旧新worker混跑的版本一致。旧上传action重放返回原记录，不自动重切或重建索引，不调用LLM/embedding。root已对SF008真实云三片source/chunks/index/vectors记录只读摘要，改动后重比；私有摘要不进入公开文档。

## 风险与缓解

| 风险                        | 缓解                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------- |
| overlap后反复选择旧end      | 两端严格增加，候选end必须带来新内容，短片/极端标点测试。                            |
| DB拒短片或放宽后允许空洞    | 按实际位置/交集验证，真PG合法/非法/回滚测试。                                       |
| 极短段落导致片数或内存超限  | 一次扫描数字边界、二分查找、实际push守5000，验证2m/5000边界。                       |
| 源码测试通过但worker仍旧lib | build core/API后重启本任务dev，用正常API/原worker新上传，禁止仅注入parser代替链路。 |
| 旧来源/向量被误改或收费     | 只读摘要前后比较，不对旧资料发重切/索引动作，不调用用户模型。                       |
