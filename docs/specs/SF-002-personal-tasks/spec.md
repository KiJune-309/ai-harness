## 背景与问题

用户希望以 Syncless 的已有功能为参照，由产品经理提出功能差距、主开发者实施、评测者给出验收结果及修改意见，按轮次推进。用户于 2026-10-17 确认本规格，并授权产品经理与评测子 agent 代为后续 SDD 阶段评审，主开发者直接计划、实现并继续轮巡。

本仓已经支持保存自定义 Agent，以及通过 DeepSeek Cordis 执行真实聊天；`apps/web/components/supporting-views.tsx` 中的 `/inbox` 任务使用前端演示数据，刷新后重置，没有真实的任务归属、服务端状态和关联 Agent 对话。因此用户虽然能创建 Agent，却不能把一个工作目标作为可追踪、可继续的任务交给它。

下述表单字段、创建后明确开始执行、状态名称、完成后只读、默认 Agent 和恢复规则均是本系统的首轮产品设计选择；官方文档只支持上述功能事实，不证明 Syncless 使用完全相同的交互。

## 目标

- 用户可以创建一个有明确目标、选定 Agent 的个人任务，并从任务页实际调用 DeepSeek Cordis 推进目标。
- 用户刷新页面或离开后返回同一任务时，能够恢复任务信息、状态和已经记录的消息；持久化承诺遵循当前实际存储模式。
- 用户能够区分工作是否完成与一次模型回答是否结束，主动标记完成或恢复任务。
- `/inbox` 展示当前身份范围内的真实任务，支持查找、按状态查看和回到原有上下文。

## 范围

### 范围内

- 以 `/inbox` 为个人任务入口，替换其前端演示任务。
- 创建包含任务名称、任务目标和 Agent 选择的个人任务；不选择自定义 Agent 时使用系统通用助手。
- 任务列表、搜索、待办与已完成视图，以及任务详情的稳定访问地址。
- 点击“开始执行”将目标记录为首条用户请求，后续有效上下文沿用这条目标及任务历史，不按轮次重复追加；同时保留 Agent 的模型、system prompt、工具和开场消息。
- 在任务中发送消息、查看流式回复、停止当前回复和继续同一上下文。
- 独立保存并手动变更任务工作状态，支持完成与恢复。
- 沿用当前 PostgreSQL 和显式开发期 memory 策略，按当前用户及工作空间隔离数据。

### 范围外

- 多成员邀请、团队角色、任务转派、Project 及其共享上下文、上下游消息。
- Project Template、自动创建下游任务、轮询触发器或定时执行。
- 文件上传、共享文件系统、资料库入库与检索、Browser/设备操作、外部工具授权。
- Agent 自动判断任务完成、自动提出状态修改，或以单次回答结束代表工作完成。
- 任务名称、目标或所用 Agent 在创建后的修改，任务删除、归档及复制。
- 把已有普通聊天或本地演示任务自动迁移为真实任务。
- 保证模型输出质量、承诺任务会被 Agent 自动完成，或在 memory 模式下承诺跨进程重启恢复。

## 用户场景

1. 用户创建“比较三个候选方案”，填写交付目标并选择已经保存的研究 Agent；创建后进入任务，看到目标与该 Agent 的开场消息，但不会仅因创建而发起付费模型调用。用户明确点击“开始执行”后，系统才将目标作为首条用户请求交给 Agent。
2. 用户在任务中补充背景，获得基于任务目标和 Agent 配置的流式回复；刷新后继续追问，Agent 仍收到该任务先前的记录与目标，不再重复追加目标或开场消息。
3. 用户发现还需要补充资料，将任务改为“待补充”；Agent 回答结束后，该任务仍保持“待补充”，直到用户主动调整。
4. 用户确认交付物可接受后标记完成；任务进入已完成视图且历史可读。稍后恢复时继续原任务和原对话，不产生另一份任务。
5. 用户在 `/inbox` 搜索任务名称或目标，从真实结果直接进入原任务。其他用户或其他工作空间无法通过猜测地址读取它。

## 非功能约束

- 基于当前 DeepSeek Cordis runtime 推进，不替换底层 Agent 执行机制；遵循 Web → contracts、API → core/db/contracts 的现有依赖边界。
- API 先校验可信身份及工作空间，再执行任务读写及模型调用；任务目标作为用户工作上下文，不得替换 Agent 既有 system prompt 或增加未授权工具。
- 状态与消息的保存不能相互覆盖；同一任务的并发生成与状态修改必须具有明确冲突行为。同一请求指同一个创建或消息动作的请求标识；不按相似文本合并用户主动发起的不同任务。请求标识相同但创建内容或消息内容不同必须拒绝，不能覆盖原记录。
- 保留现有窄屏可用性：表单、任务列表、详情和聊天在 390px 宽度下可操作；不出现必须横向滚动才能使用的核心控件。
- 表单具有关联标签、字段错误及键盘可操作性；异步加载、失败和状态变更具有可感知反馈。
- 保留普通聊天和 Agent 配置能力；新增函数遵守仓库多行 JSDoc/TSDoc 约定，执行适用测试、类型检查、构建、lint 和格式检查。

## 依赖与假设

- 用户已授权使用 Google Chrome 与公开资料研究 Syncless，但当前任务内部页面需要登录；本轮规格不依赖访问私有工作区或创建/修改 Syncless 数据。
- 当前浏览器身份由现有签名 cookie 确定；本轮不引入真实账户登录、团队切换或成员系统，不将匿名身份隔离宣传为已交付多人协作。
- 真实模型验证依赖本地已有 DeepSeek 服务端配置；密钥仅在服务端读取，不进入规格、日志、浏览器或公开响应。
- PostgreSQL 是正式持久化主记录；本地目前可能使用显式 memory 回退。AC-013 需在 PostgreSQL 环境提供证据，未执行不能标记通过。
- 创建后固定目标及 Agent 配置；首次开始执行将未开始置为进行中，此后工作状态由用户主动维护；本轮不要求 Agent 自主完成任务或管理项目流程。

## 未决问题

- 本轮切片及交互规则已由用户确认；Plan/Tasks 及后续阶段按用户授权由产品经理和评测子 agent 代审。
- Syncless 登录后的内部页面暂未实测；若后续观察改变本轮范围，必须先修订本规格并记录变化。
