## 背景与问题

SF-015 已交付工作空间边界。本项承接用户六项轮转的第二项 Project：让同一事项的负责人、共享说明和人工发布资料有清晰入口。现有 `/projects` 同时读取个人项目及协作项目，却使用不同卡片和分区；新建只创建个人项目，协作项目只能在交接时隐式产生。某些协作项目同时有同 ID 的个人项目壳，个人壳可编辑而共享详情读取另一份信息，容易出现标题和说明不同步。已有共享成果的发布入口依赖旧责任节点详情，而本人工作已转到普通聊天，用户不容易找到。

本项统一项目的发现、创建、元信息、成员及人工共享正文。既有普通聊天负责本人和 Agent 的工作；项目页负责整理事项，不重新把协作面板塞回聊天，不提前实现后续上下游、任务模板、Skills 或看板。

## 目标

- 用户从唯一“项目”入口分辨“仅自己”和“协作”，直接创建明确可见范围的项目。
- 同一个协作项目的创建者和成员看见一致的名称、说明、成员及获授权共享内容，不再因个人壳出现信息漂移。
- 拥有者可以从当前工作空间选择项目成员，用户明白加入团队不等于访问团队内所有项目。
- 有效项目成员可以人工发布和更新项目资料正文，其他有效成员可读；不自动发布私聊、调用模型或替本人向同事发消息。

## 范围

### 范围内

- `/projects` 统一项目卡片、按类型筛选、搜索、排序、去重、创建个人或协作项目。
- 协作项目详情的概览、现有工作摘要、成员和共享内容；拥有者编辑基本信息、加入或移除指定成员。
- 不依赖责任节点的项目级人工共享资料正文，作者、版本、更新时间和共享范围可辨认；保留既有已发布成果。
- 当前工作空间和项目成员双重权限、并发版本、幂等及真实 PostgreSQL 持久化。
- 旧个人项目、模板来源与任务归组保留，已有协作项目及普通聊天入口兼容。

### 范围外

- 上下游图、节点连线/拖拽、任务指派或依赖重设计、自动接力、看板和新任务状态机；这些分别在后续项定义。
- 任务模板处理人/流程编辑、Skills、设备或外部 IM。
- 项目文件上传/下载及对象存储共享、资料库文档自动共享、项目 RAG、自动把项目说明/资料注入模型上下文。
- 私有项目整体转换为协作项目、跨空间迁移、自动共享个人项目里的任务或聊天。已有 @ 只对所选工作事项的既有授权保持，不扩大成分享整个个人项目。
- 项目删除/归档、拥有者转移、成员主动退出、项目公开链接及跨工作空间成员。成员需要退出项目时本期由项目拥有者移除；退出整个团队仍按 SF-015。
- 共享资料删除、多人同时编辑富文本、附件、独立评论/消息流、模型发布或自动更新共享成果。

## 界面位置与操作流程

### 项目列表与创建

- 保留桌面侧栏、移动 Sheet 和底部导航的“项目”入口，地址仍为 `/projects`，标题“项目”，不增加第二个协作项目导航。顶部显示“当前工作空间”的说明，主要按钮“新建项目”，保留“任务模板”次要入口。
- 数量、搜索和刷新保持一行工具区域；追加单选筛选“全部 / 仅自己 / 协作”。宽度不足时纵向排列，390px 不横向滚动。
- 两类项目使用同一网格和 Card：名称、类型 Badge、说明、本人角色或“仅自己”、更新时间、短编号；协作卡可补充有效成员人数。所有可见项目整体按更新时间倒序，稳定 ID 去重；同 ID 同时存在个人壳与协作投影时，以获授权协作投影为准，不能用个人壳遮掉共享详情。
- 新建默认 Dialog 依次为名称（1–120 字）、说明（0–2000 字）、可见范围“仅自己 / 指定成员协作”。默认仅自己，保持现有个人使用习惯。协作模式显示当前空间的成员搜索和已选人员，可不选其他人先保存，也可最多选择 20 位同事；创建者自动为拥有者，不重复选择本人。
- 提交前表单始终展示完整说明和实际成员，说明“这些成员可看项目说明、工作摘要和已发布共享内容；聊天和个人资料保持私有”。一个人创建的协作项目明确“当前仅你可见，可稍后添加成员”，不伪称已邀请同事。
- 创建确认只保存项目及所选成员，不创建任务、普通聊天、Agent 开场、通知消息或模型调用。成功进入稳定 `/projects/[id]`；失败保留表单，重试不重复创建。

### 项目详情

- `/projects/[id]` 保持同一稳定路由。个人项目详情保留现有任务归组/创建/状态计数；标题区增加“仅自己”标签，返回链接统一“返回项目”，不把所有项目称为“个人项目”。
- 协作项目的标题区显示类型“协作”、名称、说明、当前空间、拥有者及真实有效成员数量；拥有者有“编辑项目”“管理成员”。随后按“项目概览 → 项目成员 → 共享内容”纵向排列，可用页内锚点帮助长页定位，不新增横向复杂导航。
- 项目概览只列现有协作工作摘要：标题、实际负责人、已有真实状态。本人有已关联普通聊天时，提供“继续我的聊天”；其他人的私有来源不提供链接。共享摘要不提供他人 prompt、完整对话或私有任务。没有工作时说明“还没有关联的协作工作”，不插入示例节点或让人误以为发布资料会执行 Agent。
- 旧 `?node=`、`?event=` 地址及已有通知继续按授权进入原工作；正常打开项目总览不强制跳普通聊天。聊天仍只保留原输入器及本人发送草稿确认，不能增加项目、上下游或回问面板。
- 项目列表/详情明确区分加载、无项目/无资料、无搜索结果和服务失败；失败有原地重试，不把共享服务失败当个人项目成功或无共享内容。

### 成员管理

- 项目拥有者与普通成员沿用两级身份，与工作空间拥有者分别判断：团队拥有者不是本项目成员时也不能读取项目。
- 项目成员卡列真实姓名、角色，重复姓名以短编号消歧。拥有者从当前有效 Workspace 成员中选择新增，提交前明确预览“将向这些人开放本项目现有及后续项目说明、工作摘要、共享正文和已发布成果”，不分享私聊或个人资料。确认成功后该人项目列表可见，不增加第二次邀请接受流程。
- 只读成员不能编辑项目、增删成员；所有有效成员可人工发布自己的项目资料，不能替他人修改。
- 移除使用确认 Dialog，展示具体成员及将失去的范围；初始焦点在取消。不能移除唯一拥有者。移除后不能继续读共享项目/内容或发布资料，相关旧协作草稿与待执行授权按原撤权语义失效；本人已投递普通消息和私有历史不删除、不移交。
- 重新加入项目必须由拥有者显式确认当前共享范围；可恢复读取已有项目共享内容，但不能恢复已取消的旧草稿、执行或责任授权。工作空间失权的人不能因项目名单仍留 ID 而访问，恢复 Workspace 资格也不自动复活旧执行。

### 人工共享内容

- 共享内容区包含“项目资料”和原有“已发布成果”。无责任节点的新项目也能发布项目资料；已有成果继续按版本展示，不伪装成新资料或丢弃历史。
- 有效成员点击“发布资料”打开默认 Dialog，输入资料标题（1–120 字）和正文（1–32000 字）。字段去首尾空白校验，正文保留内部换行；展示完整正文和“所有当前有效项目成员可见；后加入成员也可见”的范围。人工点击“发布资料”即为完整预览后的提交，不另加模型起草确认。
- 发布成功显示稳定资料 ID、作者姓名、v1、发布时间和完整可读正文；作者有“更新资料”，预填当前版，人工提交后产生 v2 等新版本。旧版本保存且可查看，列表默认展示最新版；不得覆盖掉其他作者或旧版本。项目拥有者也不能编辑其他成员的资料。
- 保存/编辑/查看零模型调用、零对外消息；发布的文字只是共享资料，不能自动触发成员的 Agent、成为系统指令或授权 Agent 发消息。Agent 身份、工具或 worker 均不能调用本期项目管理/资料发布命令。
- 发布失败保留输入和原动作标识；版本冲突显示已变更并保留本地草稿，用户重读最新资料后再明确提交，不静默覆盖或自动重发。

## 用户场景

1. 产品负责人在“产品研发”空间创建协作项目，选择设计和工程同事。三人从同一项目入口看见相同说明，未被选择的团队拥有者和同事看不到。
2. 工程在项目发布“实现约束”，设计发布“交互说明”。两份资料有独立作者与版本，成员阅读不会调用任何人的模型；工程不能改设计的资料。
3. 负责人从协作事项进入项目，发现名称不准确，在项目页修改。本人和其他成员列表/详情立即读取统一的最新名称，不出现个人壳的旧标题。
4. 旧个人项目继续管理研究任务。用户在其中某任务联系同事，只分享原确认的工作事项，其他任务和聊天不会变为全员可见。

## 非功能约束

- 保持 Web→contracts、API 授权→core/db 的依赖边界，项目管理由 API 验真实人身份，持久层复验范围与幂等；不向 Agent 增添管理/发布能力。
- 复用现有 collaboration 持久命令及动作账本，新增项目级资料可以与节点 artifact 并存，不能为了发布正文伪造责任节点、任务、聊天或用户输入。
- 共享投影字段有明确边界，不能把 private source、完整 journal、私有 prompt 或个人模型配置作为“项目内容”公开；HTML/Markdown 渲染保持现有安全规则，正文不执行。
- 成员选择显示稳定身份，发出确认前把所有后加入者可见的范围说明清楚；不增加全站账户浏览或邮箱枚举。
- 无正常内存主记录，服务错误保持已确认状态。函数多行 JSDoc/TSDoc、同级 tests、格式/lint/生产构建按仓库约定执行。
