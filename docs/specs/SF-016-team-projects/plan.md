## 技术方案与理由

复用现有 collaboration aggregate、动作账本及权限投影，增加真实人的项目管理与项目级资料命令。保持私人项目原存储；共享项目为同ID权威，不通过私有壳回退绕过撤权。用户已授权产品/实施/测试轮转，按本项spec进入实施。

## 模块、接口与数据流

- contracts：扩展共享项目、资料版本和严格人工命令；旧项目notes默认空数组，保持旧JSON可读。
- db/collaboration：创建项目无需节点；owner更新元信息/成员；有效成员发布本人资料并保留版本。锁序按Workspace/成员→aggregate→来源/动作，幂等动作先于版本判断处理原合法重放。
- API collaboration/project：真实会话活动范围和人工动作，Agent/lease显式拒绝全部本期管理/发布；旧私人更新入口不能独改共享壳。
- Web project/collaboration：统一卡片/筛选/排序，共享总览与人工表单，完整范围预览，旧显式node/event链接保留，正常项目总览不自动跳聊天。
- 共享名称更新同事务同步已存在私有壳的project字段，保留创建fingerprint与模板来源；新纯协作项目不创建私有壳、任务、聊天或模型执行。

## 数据、兼容与迁移影响

在PostgreSQL已有JSON aggregate里扩展项目级资料版本，无内存降级；旧notes缺失兼容为空。project成员与Workspace资格同时验证。移除时取消关联旧草稿/责任授权，重加不复活；普通已投递私有历史保留。无新服务/包、外部发送或依赖安装。

## 风险与缓解

| 风险                     | 影响                   | 缓解                                                      |
| ------------------------ | ---------------------- | --------------------------------------------------------- |
| 同ID私有壳遮盖/回退      | 名称漂移或绕过共享失权 | shared优先合并、API明确共享标识和权威写入、失权不fallback |
| 新command进入Agent能力   | 自动共享/伪造作者      | API/DB authorKind/lease拒绝，worker工具不增加能力         |
| 旧revision或成员撤销竞争 | 覆盖资料或失权提交     | aggregate事务/版本/动作账本，当前scope复验和撤销fence     |
| UI本地草稿被刷新覆盖     | 用户输入丢失           | 显式重读与确认，失败保稿，迟到响应忽略                    |
