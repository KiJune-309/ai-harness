## 背景与问题

用户要求点击 Agent 卡片后进入另一个页面，展示该 Agent 的详细信息。当前 `/agents` 在卡片选择后内联展开编辑器，没有可独立访问的详情地址。现有 `getAgent(id)` 与受保护的 GET API 已能读取单个真实记录，无需新增后端。

本轮将列表入口与详情浏览分开，详情默认只读，显式进入编辑后保留完整配置与真实保存功能。用户已授权产品经理及评测代理全部SDD阶段审查，无需再次人工确认。

## 目标

- Agent卡片导航到稳定详情URL，详情可直接打开、刷新与分享同一地址给有权访问者。
- 完整展示已保存配置及时间，查看不等于编辑或执行模型。
- 编辑、取消、返回、错误与身份变化正确处理草稿和范围，不能显示其他或过时记录。

## 范围

### 范围内

- `/agents` 保留现有真实方形卡片网格、空/错/忙状态和SF-012三步新建Dialog；卡片改为详情链接。
- `/agents/[id]` 独立读取、只读详情、显式完整编辑、保存/保存并聊天、本页返回列表与取消编辑的草稿保护。
- 新建有效成功后进入真实返回ID详情；默认组件、权限/Portal、移动布局、适用回归与UI规范同步。

### 范围外

- 不新增/修改Agent后端协议、字段、数据表、模型能力、权限或秘密存储；不增加删除、复制、团队分享授权或自动执行。
- 不把已有Agent编辑改成创建向导，不引入全站导航拦截或新的草稿持久化服务。

## 用户场景

1. 用户从方形卡片进入详情，查看完整提示词、工具和开场消息，也可直接打开或刷新该详情URL。
2. 用户明确点击编辑，保存后查看更新后的真实配置，或保存并开始对话；返回和取消时可保留或明确放弃未保存内容。
3. 用户新建Agent成功后直接看到它的只读详情；记录不存在、服务失败或会话失效时得到真实反馈，不展示其他Agent顶替。

## 非功能约束

- 复用现有读取/创建/更新接口与服务端范围授权，不使用前端列表或客户端header充当权限依据；不改变模型凭据/Cordis边界。
- prompt/开场是完整配置正文，纯文本显示；不因摘要截断而丢原内容，不增加自动模型请求或浏览器持久草稿。
- 原创建POST仅有同轮在途UI互斥，本轮不扩大为丢响应重试的服务端exactly-once承诺。

## 兼容与依赖

- 本Spec明确替代SF-011/012中“点击卡片后内联编辑”“创建后在列表选中并展开编辑”这两项呈现要求；旧Accepted证据保留为历史，不追溯改写。新呈现为独立只读详情与显式编辑、创建成功进入详情。
- SF-012三步创建、原完整编辑字段与两类保存、私有Portal及默认主题继续复用。辅助目录/名称加载不得造成Agent错配；具体数据与组件复用方式由Plan确定。
- 用户已授权代理全部SDD阶段；无须人工再次确认。
